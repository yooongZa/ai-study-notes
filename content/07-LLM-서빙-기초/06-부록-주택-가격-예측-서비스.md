수치 입력으로 가격을 예측하는 모델을 서비스로 제공하려면 가중치 외에도 입력 이름·열 순서·전처리 기준·출력 단위를 맞춰야 합니다. 사용자가 화면에 적은 값이 학습 때와 같은 의미의 배열로 바뀌어야 같은 계산을 수행할 수 있습니다.

이 부록에서는 **모델 학습 결과와 전처리 정보를 함께 저장하고, 새 요청의 예측으로 연결하는 과정**을 배웁니다. California Housing 예제를 통해 데이터 준비부터 회귀 모델·API·화면까지 한 흐름으로 살펴봅니다.

## 학습 목표와 흐름

| 배울 내용 | 필요한 상황 |
|---|---|
| 피처·출력 단위 | 입력과 예측값의 의미를 정할 때 |
| 분할·표준화 | 학습과 새 요청에 같은 전처리를 적용할 때 |
| 회귀 모델·오차 | 연속적인 숫자를 예측하고 성능을 평가할 때 |
| 가중치·전처리 저장 | 서버에서 학습한 계산을 복원할 때 |
| API·화면 연결 | 사용자의 값을 받아 결과를 보여줄 때 |

## 자습

### 1. 무엇을 입력받고 어떤 값을 예측하는가

회귀 모델의 숫자를 해석하려면 데이터 한 행이 무엇을 나타내는지 먼저 알아야 합니다. California Housing의 한 행은 인구조사 구역 하나이며, 여덟 가지 지역 특성으로 해당 구역의 중위 주택 가격을 예측합니다.

Regression(회귀)은 연속적인 숫자를 예측하는 작업입니다. 여기서는 정답 `MedHouseVal`의 단위가 100,000달러이므로 출력 `2.35`는 235,000달러를 뜻합니다. 이 값은 출력 단위를 설명하기 위한 예입니다.

| 순서 | 피처 | 의미 |
|---|---|---|
| 1 | `MedInc` | 중위 소득 |
| 2 | `HouseAge` | 주택 연식의 중앙값 |
| 3 | `AveRooms` | 가구당 평균 방 수 |
| 4 | `AveBedrms` | 가구당 평균 침실 수 |
| 5 | `Population` | 구역 인구 |
| 6 | `AveOccup` | 가구당 평균 거주 인원 |
| 7 | `Latitude` | 위도 |
| 8 | `Longitude` | 경도 |

입력의 값뿐 아니라 순서도 모델의 약속입니다. 첫 번째 위치에 소득으로 학습했다면 추론에서도 그 위치에 소득을 넣어야 합니다. API에서는 필드 이름으로 받고 저장한 피처 순서에 맞춰 배열을 만듭니다.

### 2. 데이터를 나눈 뒤 학습 기준으로 표준화하는 이유

소득·인구·위도는 단위와 값의 크기가 다릅니다. 피처별 평균을 빼고 표준편차로 나누면 입력의 크기를 조정할 수 있습니다. 이를 Standardization(표준화)이라고 합니다.

먼저 학습·테스트 데이터를 나누고, 학습 데이터에서만 평균과 표준편차를 계산합니다. 그 값을 테스트와 새 요청에도 적용하면 학습 때 정한 변환 기준이 유지됩니다.

$$
z_j = \frac{x_j-\mu_{\mathrm{train},j}}{\sigma_{\mathrm{train},j}}
$$

$j$는 피처의 위치이고, 평균 $\mu$와 표준편차 $\sigma$는 각 피처마다 하나씩 있습니다. 예를 들어 학습 소득 평균이 4.0, 표준편차가 2.0이면 새 입력 3.5는 $(3.5-4.0)/2.0=-0.25$로 바뀝니다.

테스트 데이터는 평가를 위해 남겨둔 자료입니다. 통계 계산도 학습 데이터로 제한해 평가 정보가 학습 준비에 섞이는 Data leakage(데이터 누수)를 막습니다. 여러 행의 배열 `(N, 8)`에 통계 `(8,)`를 적용할 때는 Broadcasting(브로드캐스팅)이 각 행에 같은 여덟 값을 사용합니다.

### 3. 회귀 모델의 입력과 정답 형태를 맞추는 방법

한 지역의 여덟 값을 넣어 가격 하나를 얻으려면 모델의 마지막 출력 크기는 1이 됩니다. 여러 지역을 묶은 배치에서는 입력 `(B, 8)`, 출력 `(B, 1)`로 계산합니다.

예제의 신경망은 **8 → 64 → 32 → 1**로 특징을 변환합니다. Linear(선형 계층)는 가중치·편향을 적용하고, ReLU(렐루)는 비선형 변환을 더합니다. Dropout(드롭아웃)은 학습 중 일부 값을 꺼 특정 특징에 대한 의존을 줄입니다.

예측이 `(B, 1)`이면 정답도 `(B, 1)`로 맞춰 같은 행끼리 비교합니다. `(B, 1)`과 `(B,)`를 빼면 브로드캐스팅으로 `(B, B)`가 만들어질 수 있으므로 손실을 계산하기 전 형태를 확인합니다.

학습은 배치 입력 → 예측 → 손실 계산 → 기울기 계산 → 가중치 갱신을 반복합니다. 평가할 때는 평가 모드로 층의 동작을 바꾸고 기울기 기록을 끕니다.

### 4. MSE와 MAE로 예측 오차를 읽는 방법

분류는 선택한 클래스가 맞는지 확인하지만, 가격 예측에서는 정답에서 얼마나 떨어졌는지를 계산해야 합니다. MSE와 MAE는 오차를 서로 다른 방식으로 모읍니다.

$$
\mathrm{MSE}=\frac{1}{N}\sum_{i=1}^{N}(\hat y_i-y_i)^2,
\qquad
\mathrm{MAE}=\frac{1}{N}\sum_{i=1}^{N}|\hat y_i-y_i|
$$

MSE(평균 제곱 오차)는 큰 오차에 더 큰 값을 부여하고, 단위도 가격 단위의 제곱이 됩니다. MAE(평균 절대 오차)는 원래 정답의 단위로 평균 차이를 표현합니다.

이 데이터에서 MAE가 0.4라면 평균 절대 오차가 40,000달러라는 뜻입니다. 이 수치는 지표를 해석하는 예시입니다. 실제 성능은 저장한 모델과 평가 데이터의 결과를 기록합니다.

배치별 평균 손실을 모을 때는 각 배치의 샘플 수를 반영하면 전체 샘플 기준 평균을 얻습니다. 모델 변경을 비교할 때는 같은 테스트 분할과 전처리 기준으로 평가합니다.

### 5. 가중치와 함께 저장해야 하는 전처리 정보

서버가 가중치를 정확히 읽어도 피처 순서나 평균·표준편차를 바꾸면 모델이 다른 입력을 받습니다. 학습 결과를 저장할 때는 추론에 필요한 정보가 한 버전으로 맞물리도록 보관해야 합니다.

| 준비물 | 추론에서 하는 일 |
|---|---|
| 모델 구조 | 가중치가 들어갈 층과 계산 순서 구성 |
| 가중치·버퍼 | 학습한 상태 복원 |
| 피처 이름·순서 | 요청 딕셔너리를 모델 배열로 변환 |
| 학습 평균·표준편차 | 학습 때와 같은 표준화 |
| 출력 단위 | 모델 숫자를 표시할 금액으로 변환 |

서버 시작 때 이 정보를 읽고 모델을 평가 모드로 준비합니다. 요청이 들어오면 검증된 값을 이름별로 꺼내 저장한 순서대로 배열을 만들고, 표준화·배치 축 추가·추론을 수행합니다.

**JSON 필드 → 피처 순서 배열 → 저장 통계로 표준화 → `(1, 8)` 텐서 → `(1, 1)` 출력 → 가격 단위 변환**

### 6. 입력 화면과 API를 하나의 예측으로 연결하기

화면에서 입력 범위를 정하면 사용자가 값을 넣기 편해집니다. API에도 필수 필드와 범위를 정의하면 화면 이외의 프로그램이 보낸 요청까지 같은 기준으로 검사할 수 있습니다.

Pydantic의 입력 모델은 여덟 필드·자료형·조건을 검사합니다. 검증을 통과한 값을 예측 함수에 전달하고, 응답에는 가격·단위·사용한 입력을 담아 결과의 의미를 확인할 수 있도록 합니다.

동기 추론을 실행자에 맡기면 이벤트 루프는 결과를 기다리는 동안 다른 요청을 처리할 수 있습니다. 작업 스레드 수와 서버 프로세스 수는 각각 메모리·실행량에 영향을 주므로 따로 정합니다.

Streamlit은 버튼을 누를 때 요청을 보내고, 성공한 입력과 결과를 세션 상태에 함께 보관합니다. 화면의 숫자를 수정한 상태와 마지막 예측에 사용한 숫자를 구분해 보여주면 사용자가 어떤 조건의 결과인지 알 수 있습니다.

모델 평가는 MSE·MAE로, 서비스 검증은 정상·잘못된 입력의 상태 코드와 응답 필드로 확인합니다. 여러 요청의 응답 시간에는 전송·대기·추론·응답이 함께 포함됩니다.
