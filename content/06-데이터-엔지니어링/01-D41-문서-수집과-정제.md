title: "D41. 문서 수집과 정제"
---

사내 규정을 검색해 답하는 챗봇을 만들려면 먼저 문서의 내용을 정확하게 읽어야 합니다. “입사 1년 미만은 별도 기준을 적용한다”는 문장이 추출 과정에서 빠지면, 검색과 답변도 그 예외를 빠뜨리게 됩니다.

여기서는 **원본 문서를 수집하고, 의미와 구조를 보존해 검색·학습에 사용할 텍스트로 만드는 방법**을 배웁니다. 문서를 읽는 방법부터 정제, 중복 확인, 개인정보 처리, 품질 검사까지 하나의 과정으로 연결합니다.

## 학습 목표와 흐름

| 배울 내용 | 필요한 상황 |
|---|---|
| 수집 목록과 메타데이터 | 문서의 출처·버전·사용 범위를 추적할 때 |
| 파일별 추출 방법 | PDF·스캔·한글 문서에서 본문과 표를 읽을 때 |
| 문자와 공백 정제 | 같은 내용을 일정한 표현으로 비교하고 검색할 때 |
| 중복과 개인정보 처리 | 반복 자료와 사용 목적에 필요 없는 정보를 정리할 때 |
| 품질 검사 | 빠진 조항이나 깨진 숫자를 검색 전에 찾을 때 |

## 자습

### 1. 수집할 문서와 출처를 함께 기록하는 이유

문서가 추가되거나 개정되면 어떤 자료를 다시 처리할지 알아야 합니다. 답변에서 잘못된 근거를 찾았을 때도 해당 원본으로 돌아갈 수 있어야 합니다. 이를 위해 본문과 함께 문서의 식별 정보와 상태를 기록합니다.

Metadata(메타데이터)는 문서 ID, 원본 위치, 수정 시각, 파일 형식, 열람 가능한 부서 같은 부가 정보입니다. 파일 이름이 바뀌어도 같은 문서인지 추적할 수 있도록, 원본 시스템이 제공하는 문서 ID를 사용하는 것이 좋습니다.

수집 시각은 시스템이 문서를 가져온 때이고, 수정 시각은 원본 내용이 바뀐 때입니다. 두 시각을 분리하면 오래된 문서를 오늘 다시 수집한 경우도 구분할 수 있습니다. 수집 목록에는 성공한 파일과 접근에 실패한 파일을 함께 기록해 전체 처리 대상이 어디까지인지 파악합니다.

### 2. 문서 형식에 맞춰 본문과 구조를 추출하는 방법

검색에는 글자뿐 아니라 문장 순서와 표의 관계도 필요합니다. 규정 표에서 “10”이라는 숫자만 읽고 “일”이라는 단위나 해당 조건을 잃으면 원래 의미를 알기 어렵습니다. 그래서 추출할 때는 파일이 내용을 저장한 방식에 맞는 도구를 사용합니다.

Parser(파서)는 파일의 내부 구조를 해석하는 프로그램입니다. PDF에는 글자와 페이지 좌표가 저장될 수 있어, 화면에 보이는 순서와 추출된 문자열의 순서가 달라질 수 있습니다. 두 단 문서는 왼쪽 문단 다음에 오른쪽 문단이 이어지는지, 표는 값의 행·열 관계가 남는지 확인합니다.

| 문서 형식 | 읽는 방법과 확인할 내용 |
|---|---|
| 텍스트가 있는 PDF | 페이지의 글자를 추출하고 문장 순서·표·반복 머리말 확인 |
| 스캔 PDF·이미지 | OCR(광학 문자 인식)로 글자를 읽고 숫자·기호 대조 |
| 일반 텍스트 | 저장할 때의 문자 인코딩으로 바이트 해석 |
| HWPX | ZIP 안의 XML에서 문단·표 구조 추출 |
| HWP | 해당 내부 형식을 지원하는 도구로 추출 |

OCR은 이미지 속 글자를 문자열로 바꿉니다. 숫자 0과 영문 O처럼 모양이 비슷한 글자는 원본과 비교합니다. 페이지 번호와 문서 ID를 추출 결과에 남기면, 나중에 문제가 생긴 위치를 쉽게 찾을 수 있습니다.

파서 선택은 문서 유형과 필요한 구조에서 시작합니다. 글자가 저장된 단순 문서는 빠른 텍스트 파서로, 표와 단 구분이 중요한 문서는 배치를 분석하는 도구로, 스캔은 OCR로 처리합니다. 같은 대표 문서에서 추출 누락·읽기 순서·처리 시간·내부 실행 가능 여부를 비교해 경로를 정합니다.

일반 본문·표·두 단 문서·스캔 문서의 대표 표본을 먼저 읽어 보면 어떤 파일에 추가 처리가 필요한지 알 수 있습니다. 글자가 거의 나오지 않는 파일은 스캔 여부, 암호화, 파서 오류를 확인해 다시 처리할 대상을 정합니다.

### 3. 문자 표현과 공백을 정리하면서 의미를 유지하는 방법

문서를 모으면 같은 글자가 서로 다른 방식으로 저장되어 있거나, 페이지마다 불필요한 공백이 섞일 수 있습니다. 정제는 이런 차이를 줄여 문서를 비교하고 검색하기 쉽게 만드는 과정입니다. 조항·문단·표의 경계는 다음 청킹 단계에서 사용할 수 있도록 남깁니다.

Encoding(인코딩)은 문자를 바이트로 저장하는 규칙입니다. UTF-8로 저장한 파일은 그 규칙으로 읽어야 원래 글자를 얻습니다. Unicode normalization(유니코드 정규화)은 이미 읽은 문자열의 표현을 맞춥니다. 예를 들어 한글 “가”는 한 글자나 자모의 조합으로 저장될 수 있습니다.

NFC는 결합할 수 있는 문자를 조합해 이런 표현을 맞춥니다. NFKC는 전각 문자나 원문자 같은 호환 표현도 정리하며, “①”을 “1”로 바꾸는 것이 한 예입니다. 문서에서 번호 모양이 구분에 사용된다면 그 의미를 유지하는 방식을 선택합니다.

공백도 위치에 따라 역할이 다릅니다. 줄 끝의 불필요한 공백은 정리하고, 제목·목록·문단 사이의 줄바꿈은 보존합니다. 반복 머리말은 여러 페이지에서 같은 위치에 나타나는지 확인한 뒤 처리합니다. “제3조”, “단위: 원”처럼 짧은 표현은 내용의 관계를 알려주므로 남깁니다.

원본과 정제본, 적용한 정제 규칙의 버전을 함께 보관하면 결과가 달라졌을 때 어떤 처리 때문인지 확인할 수 있습니다.

### 4. 같은 문서와 비슷한 문서를 구분하는 방법

같은 규정이 여러 파일에 들어 있으면 검색 결과가 반복되고 저장량도 늘어납니다. 중복을 정리할 때는 본문이 정확히 같은 자료부터 찾고, 내용이 비슷한 자료는 수치와 개정 이력을 비교합니다.

Hash(해시)는 입력 바이트를 일정한 길이의 값으로 바꾼 결과입니다. 파일 바이트의 해시는 파일 자체의 변경을 확인할 때 사용합니다. 같은 정제 규칙을 적용한 본문의 해시는 본문 중복을 찾는 데 사용합니다. SHA-256은 결과를 64자리 16진수 문자열로 표현할 수 있습니다.

본문이 일부 수정되었다면 해시는 달라집니다. 이런 유사 문서는 문자열 조각이나 의미를 비교해 후보를 찾습니다.

| 방법 | 비교하는 것 |
|---|---|
| MinHash | 문자열 조각 집합의 겹침 정도 추정 |
| LSH(지역 민감 해싱) | 비슷할 가능성이 높은 자료를 같은 후보 묶음으로 모음 |
| SimHash | 특징을 반영한 비트값에서 서로 다른 비트 수 비교 |
| 임베딩 유사도 | 문장의 의미를 벡터로 바꾸어 가까운 정도 비교 |

집합의 겹침을 나타내는 Jaccard similarity(자카드 유사도)는 교집합 크기를 합집합 크기로 나눈 값입니다. 두 문서의 문자열 조각이 대부분 겹치면 값이 커집니다.

“휴가 이월 5일”과 “휴가 이월 3일”처럼 유사한 문장에서도 업무 기준은 달라질 수 있습니다. 따라서 후보를 찾은 다음에는 수치·적용일·승인 여부를 읽고 대표 문서를 정합니다. 제외한 자료의 원본 ID와 버전 관계도 남겨 이후 개정 때 다시 확인합니다.

### 5. 사용 목적에 맞게 개인정보와 접근 범위를 처리하는 방법

고객 문의로 학습 자료를 만들 때는 질문과 해결 방법이 필요하지만 연락처는 필요하지 않을 수 있습니다. 먼저 어떤 작업에 사용할 자료인지 정한 뒤 필요한 내용과 처리할 정보를 구분합니다.

Masking(마스킹)은 연락처를 `[연락처]`처럼 바꾸는 방식입니다. 같은 사람이 여러 번 등장하는 관계를 남겨야 한다면 `고객_1`처럼 일관된 가명을 사용할 수 있습니다. 사용 목적에 필요 없는 항목은 제거하고, 허용된 범위 밖의 문서는 처리 대상에서 제외합니다.

가명과 원래 값의 대응표는 본문과 분리해 보관합니다. 문서에 남은 소속·직책·사건도 함께 검토하면 특정 사람을 알아볼 수 있는 정보를 찾는 데 도움이 됩니다.

Access control(접근 제어)은 누가 어떤 문서를 읽을 수 있는지 정합니다. 개인정보를 처리하는 작업과 함께 문서의 열람 범위도 기록해야 검색 단계에서 사용자에게 허용된 근거를 고를 수 있습니다. 문서 ID에 부서·열람 등급·처리 기준을 연결해 두는 이유입니다.

### 6. 문서 품질을 검색과 답변까지 연결해 확인하는 방법

추출 프로그램이 끝난 뒤에는 내용이 제대로 남았는지 확인해야 합니다. 추출 글자 수, 깨진 문자 비율, 페이지 누락, 표의 값 보존 여부를 살피면 다시 처리할 문서를 고를 수 있습니다.

짧은 공지와 긴 보고서는 길이가 다르므로 문서 종류별로 기준을 정합니다. 특정 문서가 이전보다 갑자기 짧아졌다면 빠진 페이지나 표가 있는지 원본과 비교합니다. 검사 결과는 통과·제외·실패와 이유로 나누어 집계합니다.

수집한 100개 문서 중 80개가 통과했다면 전체 기준 통과율은 80%입니다. 나머지가 사용 범위에 따른 제외인지, 추출 오류인지에 따라 다음 작업이 달라집니다. 분모와 상태별 건수를 함께 기록하면 처리 규칙이 바뀐 영향도 읽을 수 있습니다.

문서 품질 검사는 이후 검색과 답변 평가로 이어집니다. 정해 둔 질문으로 필요한 조항이 검색되는지 확인하고, 답변에 그 조건과 수치가 반영되는지 읽습니다. **원본 → 추출·정제본 → 검색 근거 → 답변**을 따라가면 어느 단계에서 정보가 달라졌는지 찾을 수 있습니다.
