---
title: "D45. 합성 학습 데이터 생성과 평가"
---

회의 내용을 결정 사항·담당자·기한으로 정리하는 모델을 만들려면 그 작업을 보여주는 좋은 예시가 필요합니다. 사람이 모든 예시를 작성하는 데 시간이 많이 들 때, 원문과 좋은 예시를 바탕으로 모델이 학습 후보를 만들게 할 수 있습니다.

여기서는 **합성 데이터를 생성하고 검사한 뒤, 실제로 모델 학습에 도움이 되는지 확인하는 방법**을 배웁니다. 입력과 기대 출력의 정의부터 원본 분할, 후보 생성, 선별, 학습 전후 비교까지 이어집니다.

## 학습 목표와 흐름

| 배울 내용 | 필요한 상황 |
|---|---|
| 작업과 시드 정의 | 모델에게 어떤 행동을 가르칠지 정할 때 |
| 원본 분할 | 새로운 자료에 대한 학습 효과를 평가할 때 |
| 생성과 다양성 | 필요한 유형의 학습 예시를 늘릴 때 |
| 형식·내용·분포 검사 | 잘못되거나 반복된 후보를 선별할 때 |
| 학습 효과 비교 | 데이터 선별이 실제 답변을 개선했는지 확인할 때 |

## 자습

### 1. 만들려는 학습 데이터의 목적과 형식을 정하는 방법

합성 데이터를 만들기 전에 모델이 어떤 입력을 받고 무엇을 출력해야 하는지 정합니다. 문서 질의응답이라면 질문과 근거 문서가 입력이고, 근거에 맞는 답변이 출력입니다. 회의록 정리라면 회의 내용에서 결정 사항·담당자·기한을 추출하도록 예시를 구성합니다.

Synthetic data(합성 데이터)는 규칙이나 모델로 만든 데이터입니다. 생성의 출발점이 되는 원문이나 좋은 예시를 Seed(시드 자료)라고 합니다. 시드에 답을 확인할 근거가 있어야 생성한 내용의 정확성을 검사할 수 있습니다.

| 필드 예 | 역할 |
|---|---|
| `source_id` | 근거가 된 원본 문서 추적 |
| `question` | 모델이 처리할 질문 |
| `answer` | 학습할 바람직한 답변 |
| `evidence` | 답변을 확인할 원문 근거 |
| 작업 유형 | 요약·비교·추출 등 데이터 구성 확인 |

형식을 정해 두면 빠진 필드와 잘못된 자료형을 자동으로 찾을 수 있습니다. 내용의 정확성과 함께 어느 작업을 얼마나 학습시키는지도 이 필드로 관리합니다.

### 2. 생성하기 전에 원본을 나누는 이유

같은 회의록에서 만든 질문이 학습과 시험에 나뉘어 들어가면 평가 때 익숙한 내용을 다시 만나게 됩니다. 앞으로 처음 보는 자료를 잘 처리하는지 확인하려면 원본 단위로 자료를 나누는 것이 필요합니다.

원본 문서나 회의 기록을 먼저 학습용·검증용·테스트용으로 나눕니다. 이후 생성한 질문과 답변은 원본이 속한 집합을 따릅니다. 같은 원본의 복사본·요약본·변형본도 같은 묶음으로 관리합니다.

학습용은 가중치를 학습하는 데, 검증용은 학습 설정을 선택하는 데, 테스트용은 선택을 마친 모델을 최종 평가하는 데 사용합니다. 서로 다른 ID라도 내용이 거의 같다면 중복 관계를 확인해 같은 그룹으로 묶습니다.

평가 자료에는 앞으로 처리할 주제와 시점을 반영합니다. 데이터가 부족한 작업 유형과 예외 조건도 구분해 두면 학습 후 어떤 부분이 개선됐는지 읽기 쉽습니다.

### 3. 다양한 학습 후보를 생성하는 방법

시드와 작업이 정해졌다면 필요한 종류의 입력과 답변을 생성합니다. 문서에서는 답할 수 있는 질문과 근거를 만들고, 좋은 지시·응답 예시에서는 같은 목적의 다른 사례를 만듭니다.

Self-Instruct는 좋은 지시 예시에서 새로운 지시와 응답을 생성하는 접근입니다. Evol-Instruct는 기존 지시에 조건이나 판단 단계를 추가해 난이도를 조절합니다. 문서 기반 생성에서는 예외 조항과 적용 조건을 함께 전달해야 해당 조건을 반영한 후보를 만들 수 있습니다.

다양성은 표현과 작업 조건을 함께 조정합니다. 짧은 질문·긴 질문·예외 조건·근거가 부족한 질문을 나누고, 요약·비교·정보 추출 등 필요한 작업 비율을 정합니다. 여러 판단이 필요한 질문을 추가하면 단순히 말투를 바꾼 예시와 다른 학습 경험을 만들 수 있습니다.

답변을 만드는 Teacher model(교사 모델)의 버전, 프롬프트, 시드 ID와 생성 설정을 기록합니다. 샘플링에서 `temperature`는 다음 토큰 후보의 확률 분포를 조절합니다. 출력 길이 제한 때문에 JSON이 중간에 끊겼는지도 확인합니다.

생성 전에 시드 자료와 모델의 사용 조건도 확인합니다. 원문을 외부 모델에 보낼 수 있는지, 출력물을 학습에 사용할 수 있는지, 완성한 데이터셋을 누구와 공유할 수 있는지를 각각 정합니다. 기밀 자료는 허용된 실행 환경에서 처리하고, 원문 출처·모델과 데이터의 사용 조건을 데이터 기록에 함께 남깁니다.

생성한 결과는 먼저 후보로 저장하고 검사에 통과한 항목을 학습 자료로 구분합니다. 새 후보를 다음 생성의 시드로 사용할 때도 같은 품질 검사를 거칩니다.

### 4. 형식과 답변 내용을 단계별로 검사하는 방법

생성한 질문·답변을 학습에 사용하려면 프로그램에서 읽을 수 있고, 원문에 맞는 내용이어야 합니다. 먼저 빠른 형식 검사로 기본 오류를 찾고, 다음으로 근거와 답변의 관계를 확인합니다.

| 검사 | 확인할 내용 |
|---|---|
| 구조 | JSON 파싱 성공, 필수 필드, 자료형, 빈 값 |
| 근거 | 인용한 문장이 원문에 존재하는지 |
| 내용 | 수치·단위·날짜·적용 대상·예외 조건 |
| 중복 | 같은 원본과 같은 판단이 과도하게 반복되는지 |
| 분포 | 작업 유형·주제·길이·난이도의 구성 |

원문의 “최대 5일”을 답변에서 “최소 5일”로 바꾸면 숫자는 같아도 의미가 달라집니다. 반대로 원문에 있는 3일과 2일을 합하는 질문에서는 5일이 올바른 답일 수 있습니다. 그래서 수치뿐 아니라 관계와 허용한 계산·추론을 함께 검사합니다.

생성한 질문으로 근거 문서가 검색되는지도 확인할 수 있습니다. 이 결과는 검색 가능성을 보여주며, 답변이 그 근거를 올바르게 해석했는지는 내용 검사로 확인합니다.

### 5. 모델 평가와 사람의 검수로 선별 기준을 다듬는 방법

조건의 누락이나 문맥의 오류는 단순 규칙으로 판정하기 어렵습니다. 이때 LLM-as-a-judge(LLM 평가자)를 사용해 구체적인 기준으로 후보를 검사할 수 있습니다.

평가자에게는 원문에 없는 내용 추가, 수치 변경, 적용 대상과 조건 누락을 각각 판정하도록 합니다. 판정과 문제가 된 문장을 함께 기록하면 사람이 확인하기 쉽습니다. 두 답변을 비교할 때는 제시 순서를 바꾸고, 길이·문체·생성 모델에 따른 점수 차이를 표본으로 확인합니다. 판정 형식이 깨진 결과는 재검사 대상으로 구분합니다.

사람이 검토할 표본도 목적에 맞춰 고릅니다. 새로운 오류 종류를 찾으려면 긴 문서·표·드문 주제·실패 사례를 다양하게 봅니다. 통과한 자료의 불량률을 추정하려면 통과 집합에서 무작위 표본을 뽑습니다. 탈락 자료도 읽으면 좋은 예시를 과하게 제외하는 규칙을 찾을 수 있습니다.

단계별 통과율은 후보가 어디에서 줄었는지 보여줍니다. 여기에 실제 불량 중 찾아낸 비율인 불량 적발률과, 실제 정상 중 통과시킨 비율인 정상 유지율을 함께 확인합니다. 최종적으로 정확한 답변과 필요한 유형·예외 사례가 얼마나 남았는지 살펴 선별 기준을 조정합니다.

### 6. 데이터의 버전을 남기고 학습 효과를 비교하는 방법

선별한 데이터가 준비되면 어떤 과정으로 만들었는지 기록합니다. Dataset card(데이터셋 설명서)에 목적, 입력·출력 형식, 원본과 생성 방식, 검사 기준, 분할, 주요 분포와 사용 조건을 적습니다. 데이터 버전과 내용 해시를 남기면 학습 결과를 해당 자료와 연결할 수 있습니다.

SFT(지도 미세조정)는 입력과 바람직한 출력 예시로 모델을 학습하는 방식입니다. 선별 전 자료 A와 선별 후 자료 B의 효과를 비교하려면 같은 출발 모델을 각각 불러와 별도로 학습합니다.

| 비교 조건 | 함께 맞추거나 기록할 내용 |
|---|---|
| 출발점 | 기본 모델과 어댑터 초기 상태 |
| 학습 자료 | 건수·토큰 수·작업 유형과 길이 분포 |
| 학습 설정 | 학습률·배치·반복 횟수·난수 시드 |
| 평가 | 같은 질문·생성 설정·채점 기준 |
| 비용 | 학습 시간과 사용한 계산량 |

같은 건수라도 문장이 길면 학습 토큰 수가 늘어납니다. 자료의 양과 학습량을 함께 기록하면 선별 효과를 해석하기 쉽습니다. 결과 차이가 작아 반복 편차를 확인해야 할 때는 여러 시드로 비교합니다.

학습 전 모델과 A·B로 학습한 모델을 새로운 문서와 질문에 적용합니다. JSON 형식, 수치와 조건, 담당자 추출, 근거가 부족할 때의 응답을 확인합니다. 달라진 문항을 출처와 작업 유형별로 묶으면 다음에 보완할 데이터를 찾을 수 있습니다.

## 이해 확인

> [!question]- 원본 문서를 먼저 나누고 질문을 생성하는 이유는 무엇인가요?
> 같은 원본의 변형이 학습과 평가에 섞이는 일을 줄이고, 처음 보는 자료의 처리 능력을 평가하기 위해서입니다.

> [!question]- JSON 형식 검사 뒤에는 무엇을 확인하나요?
> 근거의 존재와 답변의 수치·단위·조건·적용 대상이 원문에 맞는지 확인합니다.

> [!question]- 오류를 찾는 표본과 불량률을 추정하는 표본은 어떻게 고르나요?
> 오류 탐색은 어려운 유형과 실패 사례를 다양하게 고르고, 통과 자료의 불량률 추정은 그 집합에서 무작위로 고릅니다.

> [!question]- 선별 전후 데이터의 학습 효과를 비교할 때 출발 모델을 맞추는 이유는 무엇인가요?
> 이미 학습된 내용의 차이를 줄이고, 사용한 데이터에 따른 결과 변화를 비교하기 위해서입니다.
