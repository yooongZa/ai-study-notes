## 1. 텍스트 분류의 전체 흐름을 배우는 이유

- 같은 BERT를 사용해도 영화 리뷰의 감정과 두 문장의 의미 관계는 서로 다른 문제다.
- 모델에 넣을 글, 정답 라벨, 출력의 의미를 작업에 맞게 연결해야 한다.
- **이 연결을 이해하면 모델의 코드가 짧아져도 무엇을 학습하고 평가하는지 알 수 있다.**
- 여기서는 문장 한 개를 분류하는 경우와 문장 두 개를 비교하는 경우를 함께 살펴본다.

---

## 2. Dataset의 입력 문장과 정답 라벨

| 작업 | 데이터 한 건의 의미 |
| --- | --- |
| 감정 분류 | 리뷰 한 개와 긍정·부정 라벨 |
| 문장 유사성 분류 | 문장 두 개와 의미가 같은지 나타내는 라벨 |
| 문법 적합성 분류 | 문장 한 개와 문법적으로 자연스러운지 나타내는 라벨 |

- NSMC는 한국어 영화 리뷰의 감정 분류 데이터다. 라벨 0은 부정, 1은 긍정이다.
- MRPC는 문장 쌍이 같은 의미를 나타내는지 판단하는 데이터다.
- 라벨 1이 무엇을 뜻하는지는 데이터마다 정해진다. 모델 출력의 번호도 같은 기준으로 해석한다.
- GLUE는 영어의 여러 언어 이해 작업을 모아 평가하는 벤치마크다. 작업별 데이터와 지표를 함께 제공한다.

### datasets 모듈의 Dataset 클래스 활용

- 지도 분류 학습에서는 문장과 정답 라벨을 같은 행에 둔다. 이 대응을 유지해야 토큰화나 자료 분할 후에도 어떤 정답으로 학습할지 알 수 있다.

**코드 예시**

```python
from datasets import Dataset

data = Dataset.from_dict({
    "text": ["다시 보고 싶다.", "내용이 지루하다."],
    "label": [1, 0],
})
```

**코드 해설**

- `Dataset.from_dict()`는 딕셔너리의 열 이름과 값 목록으로 데이터셋을 만드는 클래스 메서드다.
- 첫 번째 `text`와 첫 번째 `label`이 한 행을 이룬다.
- `data[0]`은 첫 행이고, `data.column_names`는 열 이름 목록이다.
- 이 두 행은 데이터 구조를 이해하기 위한 작은 예다.

## 3. 학습·검증·테스트 데이터 분할

- Train(학습용)은 손실을 계산하고 가중치를 바꾸는 데 사용한다.
- Validation(검증용)은 학습률이나 학습 횟수를 선택하고, 어느 시점의 모델을 사용할지 판단하는 데 사용한다.
- Test(최종 평가용)는 선택을 마친 모델의 결과를 확인하는 데 사용한다.
- 같은 문장이나 같은 원문에서 나온 중복 자료가 여러 묶음에 섞이면, 이미 본 내용을 평가하게 된다.
- 중복을 정리하고 같은 원문에서 나온 자료는 같은 쪽에 배치한다.
- 결과를 비교할 때는 평가 데이터와 라벨 기준을 동일하게 유지한다.

---

## 4. Dataset의 map 메서드와 토큰화

- 아래 예시의 `tokenizer`는 앞 문서에서 불러온 모델용 토크나이저다.

- 문장 열을 모델이 읽을 토큰 번호로 바꾸되 정답과의 행 대응은 유지해야 한다. 데이터셋의 각 묶음에 같은 토크나이저를 적용해 입력 열을 추가한다.

**코드 예시**

```python
def tokenize_batch(examples):
    return tokenizer(
        examples["text"],
        truncation=True,
        max_length=64,
    )

tokenized = data.map(tokenize_batch, batched=True)
```

**코드 해설**

- `data.map()`이 행 묶음을 `tokenize_batch()`에 넣고, 함수가 반환한 숫자 입력을 새 열로 붙인다. 원래 문장·라벨과 토큰화 결과가 같은 행에 연결된다.

- `tokenize_batch`는 이 예시에서 정의한 Python 함수다.
- `Dataset.map()`은 각 행 또는 행 묶음에 함수를 적용하는 메서드다.
- `batched=True`이면 `examples["text"]`에 문자열 여러 개가 목록으로 들어온다.
- 반환한 `input_ids`와 `attention_mask` 등의 열이 데이터셋에 추가된다.
- 이때의 처리 묶음은 토큰화 함수에 여러 행을 전달하는 단위다. 모델 학습 때의 배치 크기는 별도로 정한다.
- 문장 쌍을 분류할 때는 토크나이저에 두 열을 각각 첫 번째와 두 번째 인자로 넣는다.

## 5. 동적 패딩과 DataCollatorWithPadding

- 길이가 다른 문장들을 하나의 텐서로 계산하려면 같은 길이로 맞춰야 한다.
- Dynamic padding(동적 패딩)은 현재 학습 배치의 가장 긴 문장에 맞춰 나머지를 채운다.
- Bucketing(길이가 비슷한 입력끼리 묶기)을 함께 사용하면 배치 안의 길이 차이가 작아진다.

### 길이가 3과 4인 문장을 묶는 경우

- 길이 3인 문장에 패딩 1개만 붙이면 길이 4로 맞출 수 있다.
- 길이 3과 20인 문장을 묶으면 짧은 문장에 패딩 17개가 필요하다.
- 토큰화할 때 모든 문장을 미리 최대 길이로 채우면, 배치 단계에서 길이를 줄이는 이점을 얻기 어렵다.

### transformers 모듈의 DataCollatorWithPadding 클래스

- 동적 패딩은 전체 자료의 최대 길이 대신 이번 배치의 가장 긴 문장에 맞춘다. 배치가 만들어질 때 길이를 맞추면 불필요한 빈 자리의 계산을 줄일 수 있다.

**코드 예시**

```python
from transformers import DataCollatorWithPadding

collator = DataCollatorWithPadding(tokenizer=tokenizer)
```

**코드 해설**

- Collator(배치 구성기)는 데이터 여러 건을 받아 모델에 넣을 배치로 묶는다.
- `DataCollatorWithPadding`은 토크나이저의 패딩 규칙을 사용해 입력 길이를 맞춘다.
- 데이터의 `label` 값은 모델이 받을 `labels` 텐서로 묶는다.
- 길이별 묶음의 직접적인 목적은 패딩과 계산 낭비를 줄이는 것이다. 학습 시간과 분류 성능은 각각의 지표로 확인한다.
- `TrainingArguments`의 `train_sampling_strategy="group_by_length"` 설정은 길이가 비슷한 입력을 묶는 방식을 선택한다.

## 6. 분류 로짓·정답·손실의 관계

- 긍정·부정 분류라면 문장마다 점수 두 개를 계산한다.
- 예를 들어 `[0.2, 1.8]`이라면 1번 라벨의 점수가 더 높다.
- `CrossEntropyLoss`는 이 점수와 정답 번호를 받아 손실을 계산한다.
- 학습에서는 손실의 기울기로 가중치를 갱신한다.
- 예측 결과를 읽을 때는 가장 큰 점수의 번호를 선택한다.

### torch 모듈의 argmax 함수와 클래스 선택

- 분류 결과는 문장마다 계산한 클래스 점수에서 가장 큰 위치를 골라 정한다. 모델을 학습시킬 때 사용한 라벨 번호와 같은 기준으로 해석한다.

**코드 예시**

```python
import torch

logits = torch.tensor([[0.2, 1.8], [2.1, -0.3]])
predictions = torch.argmax(logits, dim=-1)
```

**코드 해설**

- `dim=-1`은 마지막 축, 여기서는 분류 종류의 축을 뜻한다.
- 결과는 `[1, 0]`이다.
- 모델의 1번이 긍정이라는 라벨 기준을 사용하면, 첫 문장은 긍정이고 둘째 문장은 부정이다.
- 확률을 표시하고 싶으면 `torch.softmax(logits, dim=-1)`로 변환한다.

## 7. TrainingArguments와 Trainer의 역할

- 모델이 손실을 계산하는 원리는 직접 작성한 PyTorch 학습과 같다.
- `Trainer`는 배치를 가져오고, 모델을 호출하고, 역전파와 가중치 갱신을 반복하는 일을 관리한다.
- 학습 설정은 `transformers` 모듈의 `TrainingArguments` 클래스로 정한다.

- 학습 설정은 한 번에 처리할 데이터 수, 가중치 갱신 폭, 반복 횟수와 검증 시점을 정한다. 학습기를 실행하기 전에 이 기준들을 한 객체에 모아 전달한다.

**코드 예시**

```python
from transformers import TrainingArguments

args = TrainingArguments(
    output_dir="results",
    learning_rate=2e-5,
    per_device_train_batch_size=8,
    num_train_epochs=3,
    eval_strategy="epoch",
    report_to="none",
)
```

**코드 해설**

- `TrainingArguments(...)`가 학습 설정 객체를 만들며, `report_to="none"`은 외부 실험 기록 서비스로 보고하는 연동을 끈다. 배치 크기·학습률·검증 주기는 아래 인자별 설명처럼 적용된다.

- `output_dir`는 학습 결과를 저장할 위치다.
- `learning_rate`는 가중치를 얼마나 크게 바꿀지 조절한다.
- `per_device_train_batch_size`는 장치 하나가 한 번에 처리하는 학습 데이터 수다.
- `num_train_epochs`는 학습 데이터를 몇 번 반복해 볼지 정한다.
- `eval_strategy="epoch"`은 한 회차가 끝날 때 검증 데이터를 평가하도록 정한다.
- 이 코드는 설정 객체를 만든다. 실제 학습은 `Trainer` 객체의 `train()` 메서드가 시작한다.

## 8. compute_metrics 함수와 분류 성능 평가

- Accuracy(정확도)는 전체 예측 중 정답을 맞힌 비율이다.
- 정답 100건 중 90건을 맞혔다면 정확도는 0.9다.
- 어느 라벨에서 자주 틀리는지 보려면 예측 라벨과 실제 라벨을 함께 비교한다.
- 긍정을 기준으로 보면 Precision(정밀도)은 긍정이라고 예측한 문장 중 실제로 긍정인 비율이다.
- Recall(재현율)은 실제 긍정 문장 중 모델이 긍정으로 찾아낸 비율이다.
- F1은 정밀도와 재현율을 함께 반영하는 지표다.
- 모델을 선택할 때는 작업에서 중요하게 보는 지표를 정하고 검증 데이터에서 비교한다.

### 사용자 정의 compute_metrics 함수의 입력과 반환값

- 평가 단계에서는 모델의 점수를 클래스로 바꾼 뒤 같은 순서의 정답과 비교한다. 맞은 비율을 지표 이름과 함께 반환하면 학습기가 결과를 기록할 수 있다.

**코드 예시**

```python
import numpy as np

def compute_metrics(eval_pred):
    logits, labels = eval_pred
    predicted = np.argmax(logits, axis=-1)
    accuracy = (predicted == labels).mean()
    return {"accuracy": float(accuracy)}
```

**코드 해설**

- 평가 결과 두 묶음을 `logits`와 `labels`로 나눠 받는다. `np.argmax()`로 각 행의 클래스를 고른 뒤 정답과 비교한다.
- 네 예측 중 세 개가 맞으면 비교 결과의 평균은 `3/4 = 0.75`다. 반환한 `{"accuracy": 0.75}`를 Trainer가 평가 기록에 사용한다.

- 이 함수는 단일 라벨 분류의 점수를 받아 정확도를 계산한다.
- `numpy.argmax()` 함수는 각 행에서 가장 큰 점수의 위치를 찾는다.
- 배열의 `mean()` 메서드는 참을 1, 거짓을 0으로 계산한 평균을 구한다.
- `compute_metrics`를 `Trainer`에 전달하면 평가 시 이 함수를 호출한다.
- **분류의 전체 흐름은 데이터와 라벨 정의 → 분할 → 토큰화 → 배치 구성 → 미세조정 → 평가다.**
