## 1. LLM의 메모리와 계산량을 배우는 이유

- 큰 언어 모델은 학습과 답변 생성에 많은 메모리와 계산을 사용한다. 장치 용량을 넘으면 모델을 실행하기 어렵다.
- 학습 중에는 가중치, 기울기, 옵티마이저의 기록, 역전파에 필요한 중간 결과를 저장한다.
- 문장이 길어지거나 한 번에 처리하는 입력이 많아지면 중간 결과도 커진다.
- **어떤 값이 공간을 차지하는지 이해하면 LoRA·양자화·Attention 개선이 각각 무엇을 줄이는지 알 수 있다.**

---

## 2. 학습 중 저장하는 가중치·기울기·중간값

| 보관하는 값 | 필요한 이유 |
| --- | --- |
| 모델 가중치 | 입력에서 출력을 계산한다. |
| 기울기 | 가중치를 어느 방향으로 바꿀지 계산한다. |
| 옵티마이저 상태 | Adam 등에서 과거 기울기의 평균과 제곱 평균을 이용한다. |
| 중간 결과 | 역전파에서 앞선 계산을 다시 참조한다. |

- 모델을 고정하면 그 가중치의 기울기와 옵티마이저 상태를 줄일 수 있다.
- 일부만 학습해도 입력이 모델을 통과하는 계산은 필요하다.
- 저장 형식을 작게 만드는 방법과 학습할 파라미터 수를 줄이는 방법을 함께 사용할 수 있다.

---

## 3. LoRA의 작은 추가 행렬

- 전체 미세조정은 큰 가중치 행렬의 값들을 갱신한다.
- Low-rank adaptation, LoRA(작은 두 행렬로 가중치 변화를 학습하는 방법)는 기본 가중치를 고정하고 추가 변화량을 학습한다.
- 큰 변화 행렬 하나를 작은 행렬 A와 B의 곱으로 표현한다.

$$
y = Wx + \frac{\alpha}{r}BAx
$$

- `W`는 고정한 기본 가중치다.
- `A`는 입력을 작은 차원 `r`로 줄이고, `B`는 다시 출력 차원으로 늘린다.
- `r`은 두 추가 행렬 사이의 작은 중간 차원이며 Rank(랭크)라고 부른다. 작은 `r`을 쓰면 학습할 파라미터 수가 줄어든다.
- `α/r`은 추가 변화량의 비중을 조절한다.
- 입력 차원과 출력 차원이 모두 `d`라면, 큰 행렬은 `d²`개이고 추가 행렬 두 개는 `2dr`개의 파라미터를 사용한다.
- `d=1024`, `r=8`이면 기본 행렬은 1,048,576개이고, 추가로 학습할 행렬은 16,384개다.

## 4. Linear와 requires_grad_를 이용한 LoRA 계산

### torch.nn 모듈의 Linear 클래스와 Module의 requires_grad_ 메서드

- LoRA는 기본 가중치를 고정하고 작은 두 행렬로 출력에 더할 변화량을 학습한다. 큰 변환을 직접 수정하는 대신 입력을 작은 차원으로 줄였다가 다시 출력 차원으로 확장한다.

**코드 예시**

```python
import torch
from torch import nn

base = nn.Linear(4, 3, bias=False)
base.requires_grad_(False)

down = nn.Linear(4, 1, bias=False)
up = nn.Linear(1, 3, bias=False)
nn.init.zeros_(up.weight)

x = torch.tensor(1.0, 2.0, 3.0, 4.0)
y = base(x) + up(down(x))
```

**코드 해설**

- `base(x)`는 길이 4를 길이 3으로 바로 바꾸고, `up(down(x))`는 `4 → 1 → 3`으로 바꾼다. 두 결과는 모두 `(1, 3)`이므로 더할 수 있다.
- `up.weight`를 0으로 초기화했으므로 처음에는 추가 계산의 출력이 0이다. 학습에서는 작은 행렬들을 조정해 기본 출력에 더할 변화량을 배운다.

- 입력 차원 4, 출력 차원 3, 작은 차원 `r=1`인 예다.
- `base`는 기본 계산, `down`과 `up`은 추가 변화 계산을 표현한다.
- `nn.Module`의 `requires_grad_(False)` 메서드는 해당 모듈의 파라미터를 기울기 계산 대상에서 제외한다.
- `torch.nn.init.zeros_()` 함수는 전달한 텐서를 0으로 초기화한다.
- `up`을 0으로 시작하면 처음 추가 변화는 0이다. 학습하며 추가 행렬의 값이 달라진다.
- 여기서는 변화량의 비중을 1로 두었다.
- 실제 LoRA에서는 사전학습 가중치를 `base`로 사용한다. 위 코드는 계산 구조를 보여 주려고 작은 레이어를 새로 만든 예다.
- LoRA처럼 일부 파라미터만 학습하는 방식을 PEFT(파라미터 효율적 미세조정)라고 부른다.

## 5. 양자화와 비트 수 절감

- Quantization(양자화)은 가중치 등의 값을 더 적은 비트로 표현하는 방법이다.
- 16비트 값은 하나당 2바이트, 8비트 값은 하나당 1바이트를 사용한다.
- 같은 개수의 가중치를 16비트에서 8비트로 바꾸면, 가중치 값 자체를 저장하는 크기는 절반이 된다.
- 실제 모델에는 스케일 값 등 추가 정보와 다른 저장 항목도 있다.
- 양자화는 일정한 간격의 대표값으로 수를 표현하므로 원래 값과 차이가 생길 수 있다.
- LoRA는 학습할 값의 수를 줄이고, 양자화는 값을 저장하는 비트 수를 줄인다. 두 방법은 함께 사용할 수 있다.

## 6. Attention의 계산·메모리 절감 방법

- 토큰 T개가 서로를 모두 비교하면 점수의 수는 `T × T`개다.
- 길이가 2배가 되면 이 점수 수는 4배가 된다.
- Sparse attention(일부 위치만 연결하는 어텐션)은 가까운 위치 등 선택한 토큰 관계만 계산한다.
- FlashAttention은 Attention 계산을 작은 블록으로 나누어 처리하고 메모리 사이의 읽기·쓰기를 줄인다.
- 큰 점수 행렬 전체를 메모리에 보관하는 부담을 줄이면서, 정해진 Attention 연산을 계산한다.
- 두 방법을 이해할 때는 어떤 토큰 사이를 계산하는지와, 같은 계산을 어떻게 저장하고 수행하는지를 구분한다.

## 7. MoE의 전문가 선택

- 모든 토큰에 아주 큰 FFN을 적용하면 계산량도 함께 커진다.
- Mixture of experts, MoE(여러 계산 모듈 중 일부를 선택하는 구조)는 FFN 역할의 Expert(전문가 모듈)를 여러 개 둔다.
- Router(선택 모듈)는 토큰 벡터를 보고 어떤 전문가에게 보낼지 점수를 계산한다.
- Switch Transformer는 토큰마다 전문가 하나를 선택하는 구조를 사용한다.
- 전문가는 학습되는 신경망 모듈이다. 각 전문가가 처리하는 입력 패턴은 라우팅과 학습 과정에서 결정된다.

### torch 모듈의 softmax·argmax 함수와 전문가 선택

- MoE는 입력 토큰에 따라 사용할 전문가를 고른다. 라우터가 전문가별 점수를 계산하면 선택 규칙에 따라 일부 전문가로만 토큰을 보낸다.

**코드 예시**

```python
import torch

router_logits = torch.tensor([
    [1.0, 3.0, 0.0],
    [4.0, 1.0, 2.0],
])
router_probs = torch.softmax(router_logits, dim=-1)
expert_ids = torch.argmax(router_probs, dim=-1)
```

**코드 해설**

- 토큰 두 개와 전문가 세 개에 대한 점수를 가정했다.
- `torch.softmax()`는 전문가별 점수를 확률로 바꾼다.
- `torch.argmax()`는 가장 큰 확률의 전문가 번호를 고른다.
- 결과는 `[1, 0]`이다. 첫 토큰은 전문가 1, 둘째 토큰은 전문가 0으로 보낸다.
- 한 전문가에 토큰이 몰리면 처리량이 불균형해진다. 학습에서는 배분을 돕는 보조 손실과 처리 용량을 함께 고려한다.
- 모델 전체에 저장된 파라미터 수와 토큰 하나를 계산할 때 사용하는 파라미터 수를 구분한다.

## 8. 여러 장치에 계산을 나누는 방법

| 방식 | 나누는 대상 |
| --- | --- |
| Data parallelism(데이터 병렬화) | 장치마다 같은 모델을 두고 서로 다른 데이터를 처리한다. 기울기를 모아 갱신한다. |
| Model parallelism(모델 병렬화) | 한 모델의 층이나 큰 행렬을 여러 장치에 나누어 둔다. |
| Expert parallelism(전문가 병렬화) | MoE의 전문가들을 여러 장치에 나누어 배치한다. |

- 데이터 병렬화는 더 많은 데이터를 함께 처리하는 데 사용한다.
- 모델 병렬화는 한 장치에 담기 어려운 모델을 나누어 계산하는 데 사용한다.
- 장치 사이에는 중간 결과나 기울기를 주고받는 통신이 필요하다.
- 어떤 방식을 사용하느냐에 따라 나눌 데이터와 주고받을 값이 달라진다.

---

## 9. 줄일 비용에 맞는 방법 선택

- 학습할 가중치와 옵티마이저 상태가 크면 LoRA 같은 부분 학습을 생각한다.
- 가중치를 저장할 메모리가 크면 양자화를 생각한다.
- 긴 입력의 Attention 메모리가 크면 계산 방식과 연결할 위치를 살펴본다.
- 전체 모델의 표현 용량을 늘리면서 토큰당 계산을 줄이려면 MoE 구조를 살펴본다.
- 여러 장치가 있다면 데이터와 모델을 어떻게 나눌지 정한다.
- **같은 효율화라는 말 아래에서도 줄이는 대상이 다르다. 저장할 값, 학습할 값, 실제 계산량을 나누어 보면 원리가 분명해진다.**
