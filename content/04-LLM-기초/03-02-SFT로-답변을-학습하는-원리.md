## 1. 정답 답변으로 추가 학습하는 이유

- 다음 토큰 예측으로 사전학습한 모델은 여러 종류의 글을 이어 쓰는 패턴을 배운다.
- 사용자가 원하는 답변에는 질문에 직접 답하기, 정해진 형식 지키기, 필요한 내용을 빠뜨리지 않기 같은 기준이 있다.
- **질문과 좋은 답변을 짝지어 학습하면, 그 질문 뒤에 어떤 답을 생성해야 하는지 직접 알려 줄 수 있다.**
- Supervised fine-tuning, SFT(지도 미세조정)는 이런 정답 데이터를 사용해 모델을 추가 학습하는 과정이다.

---

## 2. SFT 데이터의 지시·입력·답변

- Prompt(프롬프트)는 지시와 참고 내용 등 답변을 만들 때 읽을 입력이다.
- Response 또는 Completion(답변)은 모델이 생성하도록 학습할 정답이다.
- 디코더 기반 모델에서는 프롬프트와 답변을 하나의 토큰열로 연결한다.

```text
지시: 다음 문장을 짧게 요약해 줘.
내용: 오전에 비가 내려 야외 행사가 오후로 연기됐다.
답변: 비로 인해 행사가 오후로 연기됐다.
```

- 답변의 끝에는 EOS(끝을 나타내는 토큰)를 넣어 멈출 위치도 학습한다.
- 역할 구분 기호와 줄바꿈은 모델에 맞는 대화 형식을 사용한다. 학습과 실제 질문에서 같은 형식을 유지한다.

---

## 3. 답변 토큰의 다음 토큰 예측

- 학습 데이터에는 정답 답변 전체가 있다.
- Causal mask(미래를 가리는 마스크) 때문에 각 위치는 자기 위치와 앞의 내용만 읽는다.
- 답변의 첫 토큰은 프롬프트를 읽은 상태에서 예측한다.
- 답변의 둘째 토큰은 프롬프트와 정답 첫 토큰을 읽고 예측한다.
- 정답 앞부분을 제공하면서 다음 토큰을 맞히는 방식을 Teacher forcing(정답 앞부분을 제공하는 학습)이라고 한다.
- Transformer에서는 모든 위치의 이 계산을 마스크와 함께 한 번에 처리할 수 있다.

---

## 4. 입력 토큰과 손실 라벨의 구성

- 답변을 배우려면 프롬프트를 읽어야 한다.
- 답변 부분만 손실로 계산하는 SFT에서는 프롬프트 위치의 라벨을 `-100`으로 바꾼다.
- 모델은 프롬프트를 계속 읽으면서 답변을 예측한다. `-100`은 해당 위치를 정답 채점에서 제외하는 표시다.

### Tensor의 clone 메서드와 답변 라벨 구성

- 답변 부분만 학습하는 SFT에서는 질문을 문맥으로 읽고 답변과 종료 토큰을 채점한다. 입력과 라벨을 분리하면 질문 정보는 유지하면서 손실에 포함할 위치를 조절할 수 있다.

**코드 예시**

```python
import torch

input_ids = torch.tensor(2, 8, 3, 9, 1, 0)
attention_mask = torch.tensor(1, 1, 1, 1, 1, 0)
prompt_length = 3

labels = input_ids.clone()
labels[:, :prompt_length] = -100
labels[attention_mask == 0] = -100
```

**코드 해설**

- `input_ids`의 번호는 설명용이다. `[2, 8, 3]`은 프롬프트, `9`는 답변 토큰, `1`은 EOS, `0`은 패딩이다. `prompt_length = 3`은 앞 세 토큰이 프롬프트라는 뜻이다.
- `attention_mask`의 1은 실제 입력 위치, 0은 패딩 위치다. 여기서는 마지막 자리만 패딩이다.
- `input_ids.clone()`은 PyTorch 텐서의 메서드다. 입력과 별도로 수정할 수 있는 라벨 텐서를 만들어 원래 입력값을 유지한다.
- `labels[:, :prompt_length] = -100`은 각 행의 앞 세 자리를 채점 대상에서 제외한다.
- `labels[attention_mask == 0] = -100`은 패딩 자리도 제외한다. 최종 라벨은 `-100, -100, -100, 9, 1, -100`이다.
- 답변 `9`와 EOS `1`을 맞히는 예측만 손실에 반영한다.
- 실제 데이터에서는 모델의 대화 형식에 맞춰 답변이 시작하는 토큰 위치를 정확히 구한다.

---

## 5. Causal LM의 토큰 이동과 손실 계산

- Hugging Face의 일반적인 Causal LM은 입력과 같은 위치에 놓인 `labels`를 받는다.
- 손실을 계산할 때 위치를 한 칸 맞춰, 현재 위치의 점수와 다음 토큰의 정답을 비교한다.
- 앞 예시에서 프롬프트 마지막 토큰 `3`의 출력 점수는 답변 첫 토큰 `9`와 비교한다.
- 답변 토큰 `9`의 출력 점수는 EOS `1`과 비교한다.

### Causal LM 모델 객체의 호출과 loss 속성

- 아래의 `model`은 `AutoModelForCausalLM`으로 준비한 디코더 기반 생성 모델이라고 가정한다.
- 앞 예시의 토큰 번호는 원리를 보여 주는 값이다. 실제 호출에는 그 모델의 토크나이저로 만든 번호를 넣는다.

- Causal LM의 손실 계산은 현재 위치의 점수를 다음 위치의 정답과 비교한다. 입력·실제 토큰 위치·채점할 라벨을 함께 전달하면 모델이 이 대응에 맞춰 손실을 구한다.

**코드 예시**

```python
outputs = model(
    input_ids=input_ids,
    attention_mask=attention_mask,
    labels=labels,
)
loss = outputs.loss
```

**코드 해설**

- `input_ids`는 읽을 토큰, `attention_mask`는 실제 내용의 위치, `labels`는 맞혀야 할 답을 전달한다.
- 이 예시에서 프롬프트의 마지막 토큰 다음에는 답변 9, 답변 9 다음에는 EOS 1을 예측하도록 비교한다. 이 두 예측의 손실이 `outputs.loss`에 모인다.

- `labels`는 한 칸 이동시키기 전 형태로 전달한다. 다음 토큰과의 비교는 모델의 손실 계산이 처리한다.
- `outputs.loss`는 채점 대상 토큰들의 예측 오차를 모은 값이다.
- 학습은 이 손실을 줄이도록 가중치를 조정한다.
- 프롬프트 자체를 채점에서 제외해도, 답변 예측에 사용된 프롬프트의 문맥 계산은 학습에 영향을 준다.

---

## 6. 패딩 제외와 EOS 학습

- 패딩은 배치의 길이를 맞추려고 붙인 자리이므로 정답 예측의 손실에서 제외한다.
- EOS는 답변을 끝내는 시점을 배우는 정답이므로 남긴다.
- 어떤 모델은 PAD와 EOS에 같은 토큰 번호를 사용한다.
- 이런 모델에서는 번호가 같다는 이유로 전부 제외하면 실제 답변 끝의 EOS까지 사라진다.
- `attention_mask`와 실제 길이로 패딩 위치를 구분하면, 실제 EOS는 유지하고 뒤에 붙인 자리만 제외할 수 있다.

## 7. 학습 입력과 generate 메서드의 생성 입력

| 시점 | 입력에 포함하는 내용 |
| --- | --- |
| SFT 학습 | 프롬프트와 정답 답변을 함께 넣고, 답변 토큰의 예측 손실을 계산한다. |
| 실제 생성 | 프롬프트를 넣고, 모델이 선택한 토큰을 차례로 덧붙인다. |

- 학습에서는 정답 앞부분을 참고한다.
- 실제 생성에서는 모델이 방금 만든 답변을 참고해 다음 토큰을 만든다.
- 답변이 질문에 맞는지 확인하려면, 프롬프트만 준 상태의 생성 결과를 평가한다.

### 생성 모델 객체의 generate 메서드 활용

- 아래의 `prompt_inputs`는 프롬프트만 토큰화한 텐서 묶음이다.

- 실제 답변 생성에서는 프롬프트를 읽고 토큰을 하나씩 선택해 입력 뒤에 붙인다. 생성 길이와 선택 방식을 정하면 종료 토큰 또는 길이 상한까지 이 계산을 반복한다.

**코드 예시**

```python
model.eval()
with torch.no_grad():
    generated = model.generate(
        **prompt_inputs,
        max_new_tokens=24,
        do_sample=False,
    )
```

**코드 해설**

- `eval()`로 평가 모드를 선택한 뒤 `no_grad()` 구간에서 생성한다. `generate()`에 프롬프트 묶음과 생성 옵션을 전달하면 입력과 새 답변이 포함된 토큰열을 받는다.

- `generate()`는 생성 기능을 지원하는 모델 객체의 메서드다.
- `max_new_tokens=24`는 새로 만들 토큰 수의 상한이다.
- `do_sample=False`는 무작위 추출을 끈다. 빔 개수가 1인 기본 설정에서는 매번 가장 큰 점수의 토큰을 고른다.
- EOS가 선택되면 상한에 도달하기 전에 멈출 수 있다.
- 디코더 기반 모델의 반환 토큰열에는 입력 프롬프트도 포함된다. 답변을 읽을 때는 새로 생성된 부분을 구분한다.

## 8. 좋은 SFT 데이터의 구성

- 지시와 답변이 서로 맞아야 한다. 요약 요청에 감정 분류 답이 붙으면 다른 행동을 학습한다.
- 답변이 잘린 데이터에서는 문장 마무리와 종료 위치를 배우기 어렵다.
- 같은 답변이 과도하게 반복되면 모델이 그 표현을 자주 생성하도록 학습한다.
- 학습·검증·최종 평가 자료는 같은 원문과 유사한 질문이 섞이지 않도록 나눈다.
- **SFT는 좋은 답변을 직접 보여 주는 학습이다. 여러 답변 중 어느 쪽을 더 선호하는지 배우는 과정은 다음 문서에서 다룬다.**
