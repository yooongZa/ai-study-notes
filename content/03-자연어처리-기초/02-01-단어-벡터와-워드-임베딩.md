## 1. 단어 임베딩을 배우는 이유

- 토큰 번호만 있으면 어떤 토큰인지 찾을 수 있다. 두 단어가 비슷한 문맥에 쓰이는지는 번호에서 알기 어렵다.
- `"맛있다"`와 `"훌륭하다"`가 긍정적인 리뷰에 자주 나타난다면, 모델이 이런 공통점을 학습할 수 있어야 한다.
- Vector(벡터)는 숫자를 일정한 순서로 모은 것이다.
- **단어를 벡터로 표현하면 관계를 수치로 비교하고, 그 값을 신경망의 입력으로 사용할 수 있다.**

---

## 2. CountVectorizer와 문서별 단어 빈도

- Bag of Words(단어 빈도 표현)는 문서에 어떤 단어가 몇 번 나왔는지 센다.
- 사전 순서가 `[고양이, 강아지, 좋아]`이면 `"고양이 좋아 좋아"`는 `[1, 0, 2]`로 표현한다.
- 여러 문서의 빈도 벡터를 행으로 쌓으면 Document-Term Matrix(문서 단어 행렬)가 된다.
- 각 행은 문서 하나, 각 열은 단어 하나다.
- 이 표현은 문서의 주제를 파악할 때 유용하다. 단어 순서는 저장하지 않는다.

### sklearn.feature_extraction.text 모듈의 CountVectorizer 클래스의 활용

- 문서별 단어 빈도는 각 단어가 문서에 얼마나 등장했는지 표현한다. 모든 문서에 같은 단어 순서의 열을 사용해야 문서 간 값을 비교할 수 있다.

**코드 예시**

```python
from sklearn.feature_extraction.text import CountVectorizer

vectorizer = CountVectorizer()
counts = vectorizer.fit_transform([
    "고양이 좋아 좋아",
    "강아지 좋아",
])
words = vectorizer.get_feature_names_out()
```

**코드 해설**

- `vectorizer`가 단어사전을 만든 뒤 문서마다 등장 횟수를 센다. `words`가 `["강아지", "고양이", "좋아"]`이면 첫 문서의 값은 `[0, 1, 2]`, 둘째는 `[1, 0, 1]`이다.

- `fit_transform`은 단어사전을 만들고 각 문서를 빈도 벡터로 바꾸는 메서드다.
- `get_feature_names_out`은 각 열에 대응하는 단어를 순서대로 반환한다.
- `counts`의 형태는 `(문서 2개, 단어 3개)`다.
- 많은 자리가 0이므로 결과는 Sparse matrix(희소 행렬)로 저장한다. `toarray()` 메서드로 일반적인 2차원 배열을 얻을 수 있다.

## 3. TF-IDF와 단어의 중요도

- 모든 문서에 흔하게 나오는 단어는 특정 문서의 특징을 구분하는 데 도움이 적다.
- TF(Term Frequency)는 한 문서에서 해당 단어가 나온 정도다.
- IDF(Inverse Document Frequency)는 여러 문서에서 얼마나 드물게 나오는지를 반영한다.
- TF-IDF는 두 값을 결합한다. **해당 문서에 자주 나오고, 다른 문서에는 드문 단어**가 높은 값을 받기 쉽다.
- `"고양이"`가 특정 문서에만 나오고 `"좋아"`는 모든 문서에 나온다면, 고양이가 문서를 구분하는 데 더 기여한다.
- `TfidfVectorizer`는 `CountVectorizer`와 같은 모듈에 있는 클래스다. `fit_transform` 메서드로 사전을 만들고 TF-IDF 값을 계산한다.
- 문서마다 벡터 길이를 맞추는 정규화 등도 적용하므로, 실제 출력값은 빈도에 단순히 상수를 곱한 값과 달라질 수 있다.

## 4. 원 핫 표현과 Embedding 레이어의 차이

- One-hot vector(원핫 벡터)는 해당 토큰의 자리만 1이고 나머지는 0인 벡터다.
- 토큰이 10,000개면 한 토큰을 나타내는 원핫 벡터도 길이가 10,000이다.
- 서로 다른 토큰의 원핫 벡터는 겹치는 1이 없다. 단어 간의 유사성을 표현하려면 추가 계산이 필요하다.
- Word embedding(워드 임베딩)은 각 토큰을 비교적 짧은 실수 벡터에 연결한다.
- 사전 크기가 10,000이고 벡터 차원이 128이면 임베딩 표의 형태는 `(10,000, 128)`이다.
- 한 행이 토큰 하나의 벡터다. 각 좌표의 값은 학습 과정에서 조정된다.

### torch.nn 모듈의 Embedding 클래스의 활용

- 임베딩은 토큰 번호에 대응하는 벡터를 조회하는 방식이다. 번호는 표의 행을 고르고, 그 행의 숫자들은 학습을 통해 의미 있는 표현으로 바뀐다.

**코드 예시**

```python
import torch
from torch import nn

embedding = nn.Embedding(
    num_embeddings=8, embedding_dim=4, padding_idx=0
)
ids = torch.tensor(2, 3, 0)
vectors = embedding(ids)
```

**코드 해설**

- `embedding(ids)`는 번호 2·3·0을 차례로 읽어 임베딩 표의 해당 행을 가져온다. 번호 하나가 숫자 네 개로 바뀌므로 출력에 벡터 길이 4인 축이 추가된다.
- `nn.Embedding`은 클래스이고 `embedding`은 레이어 객체다. `embedding.weight`에는 이 객체가 학습하며 사용할 표가 들어 있다.

- `ids`의 형태는 `(1, 3)`이고, `vectors`의 형태는 `(1, 3, 4)`다.
- 문장 1개에 있는 토큰 3개가 각각 길이 4의 벡터로 바뀐다.
- `embedding.weight`는 `(8, 4)` 형태의 학습 가능한 매개변수다.
- `padding_idx=0`은 패딩용 행을 지정한다. 새로 만든 이 레이어의 0번 행은 0으로 시작하며 임베딩의 역전파에서 갱신하지 않는다.
- 나머지 행은 처음에는 난수다. 손실을 줄이는 과정에서 작업에 유용한 값으로 바뀐다.
- 여기서 토큰 번호는 **행을 고르는 값**, 벡터의 좌표는 **학습으로 조정되는 값**이다.

## 5. Word2Vec의 주변 단어 예측 학습

- Distributional hypothesis(분포 가설)는 비슷한 문맥에 쓰이는 단어들이 의미상 공통점을 가진다는 생각이다.
- `"나는 커피를 마신다"`와 `"나는 차를 마신다"`에서 커피와 차는 비슷한 위치에 등장한다.
- Word2Vec은 주변 단어를 맞히는 학습을 통해 이런 사용 패턴을 벡터에 반영한다.
- Window(윈도)는 중심 단어 주변에서 함께 살펴볼 범위다.

| 학습 방식 | 예측하는 내용 |
| --- | --- |
| CBOW | 주변 단어를 보고 가운데 단어를 예측한다. `나는, 마신다 → 커피를`처럼 학습한다. |
| Skip-gram | 가운데 단어를 보고 주변 단어를 예측한다. `커피를 → 나는`, `커피를 → 마신다`처럼 쌍을 만든다. |

- 학습에서는 단어 벡터로 예측 점수를 계산하고, 실제 문맥을 잘 맞히도록 벡터를 수정한다.
- 예측을 반복하는 동안 비슷한 문맥을 가진 단어들이 관련된 벡터를 갖게 된다.

### Negative sampling의 비교 단어 선택

- 사전의 모든 단어를 매번 비교하면 계산량이 커진다.
- Negative sampling(음성 샘플링)은 실제로 관측된 단어 쌍과 무작위로 뽑은 비교용 쌍을 이용한다.
- 관측된 쌍에는 높은 점수를, 비교용 쌍에는 낮은 점수를 주도록 학습한다.
- 이때 음성은 학습에서 비교 대상으로 뽑은 단어 쌍을 가리킨다. 예를 들어 실제 주변 단어가 `우유`라면, 무작위로 뽑은 `비행기`를 비교 대상으로 사용할 수 있다.

### gensim.models의 Word2Vec 클래스와 학습 설정

- `vector_size`는 단어 벡터의 차원 수다.
- `window`는 주변 단어를 살펴보는 최대 거리다.
- `min_count`는 사전에 넣을 단어의 최소 등장 횟수다.
- `sg=0`은 CBOW, `sg=1`은 Skip-gram을 선택한다.
- 학습된 `model`의 `wv` 속성은 단어 벡터를 조회하는 `KeyedVectors` 객체다.
- `model.wv["단어"]`는 벡터를 가져온다. 이 객체의 `most_similar("단어")` 메서드는 가까운 벡터를 가진 단어를 찾는다.

## 6. FastText와 GloVe의 학습 정보

- **FastText**는 단어 안의 글자 조각도 학습한다. 예를 들어 영단어의 연속된 글자 3개나 4개가 조각이 될 수 있다.
- 여러 단어가 같은 조각의 정보를 공유하므로, 드문 단어나 학습 사전에 없는 단어도 조각을 조합해 벡터를 구할 수 있다.
- **GloVe**는 말뭉치에서 두 단어가 가까이 등장한 횟수를 모은다.
- 어떤 단어들과 얼마나 자주 함께 쓰였는지의 전체 통계를 벡터 관계에 반영한다.
- **LSA(잠재 의미 분석)**는 문서 단어 행렬을 낮은 차원으로 근사해 표현을 얻는 방법이다. 행렬에 반복되는 패턴을 적은 수의 축으로 표현한다.
- 이 방법들은 텍스트의 등장 패턴을 작은 수의 실수 값으로 표현한다는 목표를 공유한다.

## 7. 내적·벡터 길이·코사인 유사도

- Cosine similarity(코사인 유사도)는 두 벡터가 얼마나 같은 방향을 향하는지 계산한다.
- 1은 같은 방향, 0은 직각, −1은 반대 방향이다.
- 벡터의 길이보다 방향을 비교하고 싶을 때 사용한다.

$$
\operatorname{cos}(a,b)=\frac{a\cdot b}{\|a\|\|b\|}
$$

- `a·b`는 같은 위치의 값끼리 곱해서 더하는 내적이다.
- `‖a‖`와 `‖b‖`는 각 벡터의 길이다.

- 코사인 유사도는 벡터 길이를 보정한 내적으로 방향의 가까움을 비교한다. 단어 벡터의 크기보다 어떤 방향을 나타내는지가 중요할 때 사용한다.

**코드 예시**

```python
import numpy as np

a = np.array([1.0, 0.0])
b = np.array([0.8, 0.6])
similarity = np.dot(a, b) / (
    np.linalg.norm(a) * np.linalg.norm(b)
)
```

**코드 해설**

- `numpy` 모듈의 함수인 `dot`은 이 예시에서 두 벡터의 내적을 계산한다.
- `numpy.linalg` 모듈의 함수인 `norm`은 벡터의 길이를 계산한다.
- 두 벡터의 길이가 모두 1이므로 결과는 0.8이다. 계산에는 길이가 0이 아닌 벡터를 사용한다.

## 8. 고정 임베딩에서 문맥 표현으로의 확장

- Word2Vec의 `"배"`는 문장이 바뀌어도 같은 사전의 벡터를 가져온다.
- `"배를 먹었다"`와 `"배를 탔다"`를 구분하려면, 가져온 벡터에 주변 문장의 정보를 반영해야 한다.
- Contextual representation(문맥을 반영한 표현)은 같은 토큰이라도 주변 내용에 따라 다른 벡터를 계산한다.
- ELMo는 양방향 LSTM을, Transformer 계열은 Attention 등을 사용해 문맥을 반영한다.
- **토큰 번호 → 기본 임베딩 → 주변 토큰과의 관계 계산 → 문맥을 반영한 벡터**의 순서로 이해하면 된다.
