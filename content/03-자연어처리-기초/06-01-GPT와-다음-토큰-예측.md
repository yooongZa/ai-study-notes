## 1. GPT의 다음 토큰 예측을 배우는 이유

- 챗봇의 답변은 한 번에 완성된 문장으로 보이지만, 모델은 앞의 내용을 읽고 다음 토큰을 선택하는 계산을 반복한다.
- `"오늘 날씨가"` 다음에는 `"좋다"`, `"흐리다"`처럼 여러 후보가 있을 수 있다.
- 모델은 각 후보에 점수를 주고, 선택된 토큰을 앞의 내용에 붙여 다음 계산을 한다.
- **다음 토큰 예측을 이해하면 입력 형식, 학습 정답, 미래 마스크, 생성 방식을 함께 연결할 수 있다.**

---

## 2. GPT의 디코더 블록 구조

- 번역 Transformer는 원문을 읽는 인코더와 번역문을 만드는 디코더가 연결되어 있다.
- GPT는 입력으로 받은 글의 뒤를 이어 쓰는 Decoder-only(디코더 중심) 구조를 사용한다.
- 이전 토큰을 참고하는 Masked self-attention과 FFN을 여러 층 쌓는다.
- 별도의 인코더 출력을 읽는 Cross-attention은 이 기본 GPT 구조에 들어가지 않는다.
- 입력과 지금까지 생성한 내용이 같은 토큰열 안에 놓인다.
- 각 위치의 출력 벡터를 사전 크기의 로짓으로 바꿔 다음 토큰을 예측한다.

### GPT의 기본 계산 순서

1. 토큰 번호에서 임베딩 벡터를 가져온다.
2. 위치 정보를 더한다.
3. 미래를 가린 Self-attention으로 앞 문맥을 반영한다.
4. FFN으로 각 위치의 표현을 변환한다.
5. 잔차 연결과 정규화를 포함한 블록을 여러 층 통과한다.
6. 출력층에서 다음 토큰 후보들의 점수를 구한다.

---

## 3. 토큰 임베딩과 학습 가능한 위치 임베딩

- GPT의 각 토큰은 의미를 나타내는 기본 임베딩과 문장 안의 위치 정보를 함께 받는다.
- 원래 GPT인 GPT-1은 학습 가능한 Position embedding(위치 임베딩)을 사용한다.
- 위치 0, 1, 2 등에 해당하는 벡터가 있으며, 학습하면서 값이 바뀐다.
- GPT-1의 FFN에는 GELU 활성 함수가 사용된다. 입력의 크기에 따라 값을 부드럽게 조절한다.

### torch.nn 모듈의 Embedding 클래스와 토큰·위치 표현

- 토큰의 종류와 위치는 서로 다른 정보다. 각각의 임베딩을 같은 크기로 만든 뒤 더하면 이후 Attention이 내용과 순서를 함께 참고할 수 있다.

**코드 예시**

```python
import torch
from torch import nn

ids = torch.tensor(2, 5, 7)
token_embedding = nn.Embedding(10, 4)
position_embedding = nn.Embedding(8, 4)

positions = torch.arange(ids.size(1)).unsqueeze(0)
x = token_embedding(ids) + position_embedding(positions)
```

**코드 해설**

- 토큰 사전은 10개, 위치는 최대 8개, 벡터 차원은 4인 작은 예시다.
- `Tensor.size(1)`은 문장 길이 3을 반환한다.
- `torch.arange(3)`은 위치 번호 `[0, 1, 2]`를 만든다.
- `Tensor`의 메서드인 `unsqueeze(0)`은 앞에 크기 1인 축을 추가해 `0, 1, 2`로 만든다.
- 두 임베딩 결과는 모두 `(1, 3, 4)`이므로 같은 위치끼리 더할 수 있다.
- `x`에는 토큰과 위치의 정보가 함께 들어간다. 실제 문맥 관계는 이후 Attention 블록에서 계산한다.
- 이 예시에서 새로 만든 임베딩은 아직 학습되지 않은 값이다.

## 4. 다음 토큰 예측의 입력과 정답

- 이해를 위해 `"나는 밥을 먹는다"`를 세 토큰으로 나눈다고 하자.
- 문장 전체를 `[<bos>, 나는, 밥을, 먹는다, <eos>]`로 만든다.
- 입력은 마지막 토큰을 뺀 것이고, 정답은 첫 토큰을 뺀 것이다.

| 입력 위치 | 그 위치에서 맞힐 정답 |
| --- | --- |
| `<bos>`까지 읽음 | `나는` |
| `나는`까지 읽음 | `밥을` |
| `밥을`까지 읽음 | `먹는다` |
| `먹는다`까지 읽음 | `<eos>` |

- 학습에서는 정답 문장을 한꺼번에 넣지만, 각 위치는 미래 마스크 때문에 자기 위치와 앞부분만 참고한다.
- 각 위치의 로짓과 정답 토큰 번호로 손실을 구한다.
- 이를 많은 문장에 반복하면 어떤 문맥에 어떤 표현이 이어지는지 학습한다.
- Next-token prediction(다음 토큰 예측)은 문장 자체에서 정답을 만들 수 있다. 사람이 토큰마다 정답 표시를 새로 붙일 필요가 없다.

## 5. 대화 역할과 토큰 순서

- 질문과 답변을 학습하려면 누가 말한 부분인지와 어디서 답변이 시작하는지 표시한다.
- 설명을 위한 형식으로 다음과 같이 구성할 수 있다.

```text
<user> 안녕 <assistant> 반가워 <eos>
```

- `<user>`, `<assistant>`는 역할 구분을 설명하기 위해 쓴 기호다. 실제 형식은 사용하는 모델과 토크나이저가 정한다.
- 모델은 질문과 역할 표시를 읽고 답변 토큰을 예측한다.
- 실제 답변을 생성할 때는 `<user> 안녕 <assistant>`까지 넣고, 뒤에 이어질 토큰을 만든다.
- 여러 차례의 대화라면 이전 질문과 답변을 정해진 순서로 함께 넣는다.
- 모델이 한 번에 참고할 수 있는 토큰 범위인 Context window(문맥 길이) 안에 입력과 생성할 내용이 들어가야 한다.

## 6. Attention 위치와 손실 계산 위치

- 대화 학습에서는 질문도 읽게 하면서, 답변을 예측하는 위치에만 손실을 계산할 수 있다.
- Causal mask는 각 위치에서 미래 토큰을 참고하지 못하게 한다.
- Loss mask(손실 계산 위치 표시)는 어떤 정답을 학습 점수에 포함할지 정한다.
- 질문을 손실에서 제외해도 답변을 생성하는 데 필요한 문맥으로는 읽을 수 있다.

### Tensor의 clone 메서드와 손실의 ignore_index 설정

- 아래 번호는 설명용이다. `[4, 5, 6]`은 역할 표시를 포함한 질문 부분이고, `[7, 2]`는 답변 토큰과 종료 토큰이라고 하자.

- 답변만 채점하는 학습에서도 질문은 입력 문맥으로 필요하다. 입력 토큰은 유지하고, 한 칸 뒤의 정답 중 답변·종료 위치만 손실에 포함한다.

**코드 예시**

```python
tokens = torch.tensor(4, 5, 6, 7, 2)
input_ids = tokens[:, :-1]
labels = tokens[:, 1:].clone()
labels[:, :2] = -100

criterion = nn.CrossEntropyLoss(ignore_index=-100)
```

**코드 해설**

- `labels`에는 입력 `tokens`에서 한 칸 뒤의 값을 복사한다. 복사한 쪽만 수정해 앞의 두 정답을 `-100`으로 바꾸면, 질문은 읽으면서 답변 부분의 손실만 계산하는 학습 자료가 된다.

- 입력은 `[4, 5, 6, 7]`이다. 한 칸 이동한 정답은 원래 `[5, 6, 7, 2]`다.
- 정답 앞의 두 위치를 제외하면 `[-100, -100, 7, 2]`가 된다.
- 모델은 질문을 읽되, 답변 7과 종료 2를 예측하는 위치의 손실로 학습한다.
- `clone()`은 원본 `tokens`를 바꾸지 않도록 별도 텐서를 만든다.
- `-100`은 정답인 `labels`에서 손실을 제외할 위치를 표시한다. 모델 입력인 `input_ids`에는 원래 토큰 번호를 유지한다.
- 실제 질문·답변의 경계에 맞춰 제외할 위치를 정해야 한다.

## 7. 확률·Temperature·샘플링의 관계

- 같은 로짓이라도 선택 규칙에 따라 생성 결과가 달라진다.
- Greedy decoding은 가장 높은 점수의 토큰을 고른다.
- Sampling(샘플링)은 확률에 따라 토큰을 뽑는다. 낮은 확률의 토큰도 선택될 수 있다.
- Temperature(온도)는 Softmax 전에 로짓을 나누는 양수 값이다.
- 온도가 작으면 높은 점수에 확률이 더 모이고, 크면 후보들의 확률 차이가 완만해진다.

### torch 모듈의 softmax·multinomial 함수 활용

- 샘플링은 토큰별 확률에 따라 다음 토큰을 뽑는 방식이다. 온도로 점수 차이를 조정하면 높은 점수에 선택을 집중할지, 여러 후보에 분산할지 바꿀 수 있다.

**코드 예시**

```python
logits = torch.tensor([2.0, 1.0, 0.0])
temperature = 0.5

probs = torch.softmax(logits / temperature, dim=-1)
next_id = torch.multinomial(probs, num_samples=1).item()
```

**코드 해설**

- 계산 순서는 **로짓을 온도로 나누기 → Softmax로 확률 계산 → 확률에 따라 번호 선택 → Python 정수로 꺼내기**다.
- 선택된 `next_id`는 사전의 한 토큰을 가리킨다. 번호를 입력 뒤에 추가하고 같은 과정을 반복하면 여러 토큰으로 된 답변이 만들어진다.

- 온도 1일 때 확률은 약 `[0.665, 0.245, 0.090]`이다.
- 온도 0.5에서는 약 `[0.867, 0.117, 0.016]`으로 가장 높은 점수에 더 모인다.
- `multinomial`은 전달된 확률에 따라 인덱스를 뽑는 함수다.
- `num_samples=1`은 한 개를 선택한다. 실행할 때 선택 결과가 달라질 수 있다.
- `item()`은 선택된 번호를 Python 숫자로 꺼낸다.
- Top-k는 확률이 높은 후보 `k`개 안에서, Top-p는 높은 확률부터 더해 누적 확률 `p`에 도달하는 후보 집합 안에서 선택한다.

## 8. 토큰 선택과 입력 확장의 반복

- 현재 입력의 마지막 위치에서 다음 토큰의 로짓을 가져온다.
- 토큰 하나를 선택해 입력 뒤에 붙인다.
- 새로운 전체 입력을 바탕으로 다음 토큰을 다시 예측한다.
- 종료 토큰이나 최대 생성 길이에 도달하면 멈춘다.
- Autoregressive generation(앞서 생성한 결과를 다시 사용하는 생성)은 이 반복 방식을 뜻한다.
- 앞에서 선택한 내용이 다음 계산의 문맥이 되므로, 첫 선택들이 뒤 문장에도 영향을 준다.

---

## 9. 사전학습과 대화 학습의 연결

- Pretraining(사전학습)은 많은 텍스트에서 다음 토큰을 예측하며 언어의 사용 패턴을 학습하는 과정이다.
- Fine-tuning(미세조정)은 기존 가중치를 출발점으로 특정 작업의 데이터에 맞춰 더 학습하는 과정이다.
- 대화 데이터로 미세조정하면 질문과 답변 형식에 맞는 이어쓰기를 배울 수 있다.
- Prompt(프롬프트)는 생성할 때 모델이 읽는 입력이다. 이때 제공한 문맥을 바탕으로 출력이 달라진다.
- 미세조정은 가중치를 바꾸고, 일반적인 생성은 준비된 가중치로 입력의 다음 토큰을 계산한다.
- **문장 나누기 → 토큰 번호 → 토큰·위치 임베딩 → 미래를 가린 문맥 계산 → 다음 토큰 점수 → 선택과 반복**이 앞에서 배운 내용을 연결하는 GPT의 기본 흐름이다.

## 10. Perplexity와 다음 토큰 예측의 평가

- 문장을 생성하는 모델도 학습이 얼마나 잘됐는지 비교할 숫자가 필요하다.
- 평가 문장의 앞부분을 입력하고, 실제 다음 토큰에 모델이 준 확률을 확인한다.
- Perplexity(퍼플렉서티)는 이 확률들로 계산한 평가 지표다.
- 정답 토큰에 높은 확률을 줄수록 값이 작아진다.

### 10-1) 정답 확률에서 평균 손실과 Perplexity까지

1. 각 위치에서 정답 토큰에 준 확률 `p`를 가져온다.
2. `-log(p)`를 계산해 그 위치의 손실을 구한다.
3. 평가에 포함한 토큰들의 손실을 평균한다.
4. 자연로그로 구한 평균 손실에 지수함수 `exp()`를 적용한다.

$$\mathrm{PPL}=\exp(\text{평균 음의 로그우도})$$

### 10-2) Python math 모듈의 log·exp 함수 활용

- Perplexity는 정답 토큰에 준 평균 로그 손실을 지수로 바꾼 값이다. 정답에 높은 확률을 줄수록 평균 손실과 Perplexity가 함께 낮아진다.

**코드 예시**

```python
import math

correct_probs = [0.5, 0.5]
mean_loss = sum(-math.log(p) for p in correct_probs) / 2
perplexity = math.exp(mean_loss)
print(round(mean_loss, 3))   # 0.693
print(round(perplexity, 3))  # 2.0
```

**코드 해설**

- `mean_loss`는 두 정답 확률의 음의 로그를 더해 평균한다. `math.exp()`가 그 평균을 Perplexity로 바꾸고, 마지막 두 줄이 손실과 PPL을 각각 출력한다.

- 두 정답 토큰에 각각 0.5의 확률을 주면 평균 손실은 약 0.693, PPL은 2다.
- 각각 0.25를 주면 평균 손실은 약 1.386, PPL은 4다.
- 이처럼 정답에 준 확률이 작아지면 손실과 PPL이 함께 커진다.
- 실제 평가에서는 패딩을 제외하고, 유효한 정답 토큰 수로 평균을 낸다.
- 모델끼리 비교할 때는 평가 문장, 토크나이저, 앞 문맥의 길이를 맞춘다. 이 조건들이 예측 확률과 평균에 포함되는 토큰 수를 결정한다.
