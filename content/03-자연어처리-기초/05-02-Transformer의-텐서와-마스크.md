## 1. Attention의 텐서 축과 마스크가 필요한 이유

- Attention 코드는 토큰, 문장, 헤드를 여러 축으로 묶어서 계산한다.
- 축의 뜻을 놓치면 어떤 토큰을 비교하는지, 무엇을 가리는지 이해하기 어렵다.
- 마스크가 없으면 디코더가 학습 중에 미래 정답을 읽거나, 패딩을 실제 내용으로 참고할 수 있다.
- **어떤 정보를 담은 축인지와 어떤 위치를 가리는지**를 먼저 알면 계산의 흐름을 읽을 수 있다.

---

## 2. 토큰 번호·임베딩·출력 점수의 형태

- 배치 크기를 `B`, 원문 길이를 `S`, 번역문 길이를 `T`라고 하자.
- 모델 벡터 차원은 `D`, 목표 언어 사전 크기는 `V`다.
- 아래는 배치가 첫 축인 `batch_first=True` 방식이다.

| 단계 | 텐서의 형태와 의미 |
| --- | --- |
| 원문 토큰 번호 | `(B, S)`. 문장마다 원문 토큰 번호가 있다. |
| 원문 임베딩과 인코더 출력 | `(B, S, D)`. 원문의 각 위치를 길이 `D`의 벡터로 표현한다. |
| 디코더 입력 번호 | `(B, T)`. 생성할 문장의 앞부분이다. |
| 디코더 출력 벡터 | `(B, T, D)`. 각 위치의 문맥 정보다. |
| 최종 로짓 | `(B, T, V)`. 각 위치에서 다음 토큰 후보 `V`개에 점수를 준다. |

- 원문 길이 `S`와 번역문 길이 `T`는 서로 달라도 된다.
- Cross-attention은 번역문의 각 위치가 원문의 각 위치를 참고하므로, 헤드 하나의 가중치 형태가 `(B, T, S)`다.

## 3. reshape·permute와 헤드 분리

- `D=8`을 헤드 2개로 나누면 헤드당 차원은 4다.
- 먼저 마지막 축을 `(헤드 2개, 각 4차원)`으로 나누고, 계산하기 편하게 헤드 축을 옮긴다.

### torch Tensor의 reshape·permute 메서드와 축 배치

- 여러 Attention 헤드를 따로 계산하려면 벡터 차원을 헤드 수와 헤드별 차원으로 나누어야 한다. 이어서 헤드 축을 옮겨 각 헤드의 토큰 간 비교를 한꺼번에 계산할 수 있게 배치한다.

**코드 예시**

```python
import torch

x = torch.arange(48).reshape(2, 3, 8)
heads = x.reshape(2, 3, 2, 4).permute(0, 2, 1, 3)
```

**코드 해설**

- 두 메서드는 순서대로 적용된다. 먼저 마지막 길이 8을 `헤드 2개 × 헤드당 길이 4`로 나누고, 헤드 축을 앞으로 옮겨 헤드별 계산을 준비한다.

- `x`는 `(배치 2, 길이 3, 차원 8)`이다.
- `reshape(2, 3, 2, 4)`는 벡터 차원을 헤드와 헤드별 차원으로 나눈다.
- `permute(0, 2, 1, 3)`는 축을 `(배치, 헤드, 길이, 헤드 차원)` 순서로 바꾼다.
- `heads`의 형태는 `(2, 2, 3, 4)`다.
- 각 헤드에서 Attention을 계산한 뒤, 축을 되돌리고 헤드별 출력을 이어 붙여 모델 차원으로 합친다.
- Query와 Key의 마지막 두 축을 곱하면 토큰 위치끼리의 점수 행렬이 된다.

## 4. 미래 토큰 마스크와 Softmax 계산

- 디코더 입력이 `[<bos>, I, eat]`라면 각 위치의 정답은 `[I, eat, apples]`다.
- 첫 위치는 `<bos>`만 읽고 `I`를 예측해야 한다.
- 둘째 위치는 `<bos>, I`를 읽고 `eat`을 예측한다.
- 셋째 위치는 세 토큰을 모두 읽고 `apples`를 예측한다.
- 자신의 오른쪽 위치를 가리면 이 조건을 행렬로 한 번에 적용할 수 있다.

![[03-자연어처리-기초/assets/미래-토큰-마스크.png]]

- 왼쪽 그림은 각 행의 위치에서 참고할 수 있는 열을 나타낸다.
- 오른쪽은 예시 점수에 마스크와 Softmax를 적용한 결과다. 가린 자리의 가중치는 0이고, 각 행의 합은 1이다.
- 첫 행이 둘째 열의 `I`를 읽으면 지금 맞혀야 할 정답을 입력에서 보게 된다. 그래서 첫 행에서는 그 열을 가린다.

### torch 모듈의 triu 함수의 활용

- 생성 모델의 학습에서는 현재 위치가 오른쪽의 정답을 미리 참고하지 않도록 가린다. 행을 현재 위치, 열을 참고 위치로 보면 대각선 위쪽이 미래에 해당한다.

**코드 예시**

```python
future_mask = torch.triu(
    torch.ones(3, 3, dtype=torch.bool), diagonal=1
)
```

**코드 해설**

- `ones(3, 3, dtype=torch.bool)`이 참으로 채운 표를 만든다. `triu(..., diagonal=1)`은 대각선 위만 참으로 남겨 미래 위치 표시를 만든다.

- 결과의 각 행은 `[False, True, True]`, `[False, False, True]`, `[False, False, False]`다.
- `diagonal=1`은 대각선 바로 위부터 선택한다. 자기 위치와 이전 위치는 남긴다.
- 이 예시에서 `True`는 가릴 자리로 사용한다.

### torch Tensor의 masked_fill 메서드의 활용

- Softmax 계산 전에 가릴 위치의 점수를 음의 무한대로 바꾸면 그 위치의 비율은 0이 된다. 남은 위치끼리 비율을 나누어 갖게 하는 방식으로 정보 참조 범위를 제한한다.

**코드 예시**

```python
scores = torch.tensor([
    [1.0, 2.0, 3.0],
    [1.0, 2.0, 3.0],
    [1.0, 2.0, 3.0],
])
masked_scores = scores.masked_fill(future_mask, float("-inf"))
weights = torch.softmax(masked_scores, dim=-1)
```

**코드 해설**

- 첫 행은 첫 토큰이 참고할 위치를 나타낸다. 미래 두 위치를 가리면 Softmax 결과가 `[1, 0, 0]`이 되어 자기 위치만 사용한다.
- 둘째 행은 앞의 두 위치에만 비율을 주고, 셋째 행은 세 위치 모두에 비율을 준다. 이후 이 비율로 Value 벡터를 섞는다.

- `masked_fill`은 마스크가 `True`인 자리의 점수를 `-inf`로 바꾼 새 텐서를 반환한다.
- Softmax에서 `-inf`에 해당하는 자리는 확률 0이 된다.
- `dim=-1`은 각 행에서 참고 대상인 열들을 기준으로 비율을 구한다.
- 적어도 하나의 유효한 참고 위치가 남아 있어야 한 행의 비율을 계산할 수 있다.

## 5. 패딩 마스크와 유효한 토큰 위치

- 미래 마스크는 위치 사이의 순서를 제한한다.
- Padding mask(패딩 마스크)는 문장마다 다른 빈 자리를 가린다.
- 인코더 Self-attention은 원문의 패딩을 가린다.
- 디코더 Self-attention은 미래 위치와 목표 문장의 패딩을 가린다.
- Cross-attention은 Key와 Value에 해당하는 원문의 패딩을 가린다.
- 패딩인 출력 위치의 정답은 손실에서도 제외한다. Attention의 마스크와 손실의 제외 설정은 따로 적용된다.

## 6. MultiheadAttention 클래스의 인자와 반환값

### torch.nn 모듈의 MultiheadAttention 클래스의 활용

- Multi-head Attention은 여러 헤드에서 참고 비율과 가중합을 구한 뒤 결과를 합친다. 마스크를 전달하면 각 헤드가 허용된 토큰만 참고하고, 헤드별 비율도 따로 확인할 수 있다.

**코드 예시**

```python
from torch import nn

attn = nn.MultiheadAttention(
    embed_dim=8, num_heads=2, batch_first=True, dropout=0.0
)
x = torch.zeros(2, 3, 8)

out, weights = attn(
    x, x, x,
    attn_mask=future_mask,
    need_weights=True,
    average_attn_weights=False,
)
```

**코드 해설**

- 첫 줄에서 모델 차원 8을 헤드 2개로 나눈 레이어를 준비한다. `attn(x, x, x, ...)`가 같은 입력으로 Self-attention을 계산하며, `out`에 새 벡터를, `weights`에 참고 비율을 반환한다.

- 앞의 세 `x`는 각각 Query, Key, Value를 만들 입력이다. 같은 입력을 전달하므로 Self-attention이다.
- 이 클래스가 내부에서 Query·Key·Value를 가중치로 변환한다.
- `attn_mask`에 전달한 Boolean mask(참·거짓 마스크)는 **True인 위치를 가린다**.
- `out`의 형태는 `(2, 3, 8)`이다.
- `average_attn_weights=False`이면 헤드별 가중치를 따로 받는다. `weights`의 형태는 `(2, 2, 3, 3)`이다.
- `key_padding_mask`에는 `(B, S)` 형태의 패딩 표시를 전달한다. 이 인자도 True인 Key 위치를 가린다.
- Cross-attention에서는 첫 인자에 디코더 표현, 둘째·셋째 인자에 인코더 출력을 전달한다.
- 마스크의 참·거짓 의미는 사용하는 함수의 정의를 따른다. 위 설명은 `nn.MultiheadAttention`과 이 문서의 `masked_fill` 예시에 해당한다.

## 7. 레이어·위치 정보·학습 값의 관리

- 여러 Transformer 레이어를 쌓으면 각 층이 앞 층의 출력을 다시 계산한다.
- `torch.nn` 모듈의 클래스인 `ModuleList`는 여러 레이어를 모델의 구성 요소로 등록해서 보관한다.
- 등록된 레이어는 `model.parameters()`와 저장할 가중치 목록에 포함된다. 실제 적용 순서는 `forward` 안의 반복문이 정한다.
- `nn.Module` 객체의 메서드인 `register_buffer`는 학습 매개변수는 아니지만 모델과 함께 관리할 텐서를 등록한다.
- 사인·코사인으로 만든 위치 인코딩은 이런 Buffer(버퍼)에 저장할 수 있다.
- `model.to(device)`로 장치를 옮기면 버퍼도 함께 이동한다.

### 가중치 공유와 학습률 조절

- Weight tying(가중치 공유)은 토큰 임베딩의 가중치를 출력층에서도 공유하는 방법이다.
- 임베딩은 번호에서 벡터를 찾고, 출력층은 벡터에서 토큰별 점수를 계산한다. 같은 목표 언어 사전과 맞는 차원을 사용해야 한다.
- Learning rate scheduler(학습률 조절기)는 학습 진행에 따라 갱신 폭을 바꾼다.
- Warmup(초기 학습률 증가)은 초반에 작은 학습률로 시작해 점차 키우는 과정이다.
- 이후 학습률을 낮추면 후반의 갱신 폭을 줄일 수 있다.
- `torch.optim.lr_scheduler` 모듈의 `LambdaLR` 클래스는 사용자가 정의한 함수로 학습률 배율을 정한다.

## 8. 학습과 생성의 텐서 흐름

1. 원문과 번역문을 토큰 번호로 바꾸고 배치로 묶는다.
2. 번역문을 한 칸 이동해 디코더 입력과 정답을 만든다.
3. 원문 패딩, 목표 패딩, 미래 위치를 표시한다.
4. 인코더와 디코더에서 문맥 벡터를 계산한다.
5. 출력층에서 목표 사전 크기의 로짓을 구한다.
6. 패딩을 제외해 손실을 계산하고 가중치를 갱신한다.

- 실제 생성에서는 디코더 입력의 **마지막 위치 로짓**으로 다음 토큰을 고른다.
- 고른 토큰을 입력 뒤에 붙이고, 늘어난 길이에 맞춰 미래 마스크도 적용한다.
- `<eos>`나 최대 길이에서 생성이 끝나면 목표 언어 토크나이저로 번호를 텍스트로 바꾼다.
