## 1. 요약 데이터와 평가 기준이 필요한 이유

- 문장을 자연스럽게 만드는 것과 원문의 핵심을 정확히 전달하는 것은 함께 확인해야 할 목표다.
- 모델은 본문과 정답 요약문에 나타난 관계를 배운다. 두 열이 어긋나거나 내용이 빠지면 잘못된 관계를 학습한다.
- 평가 기준을 이해하면 손실이 줄었다는 결과와 실제 요약 품질을 연결해서 읽을 수 있다.
- **요약에서는 핵심 내용, 사실 관계, 문장의 이해 가능성, 길이를 함께 살펴본다.**

---

## 2. 본문과 정답 요약문의 대응

- 뉴스 데이터의 `text`는 기사 본문, `headlines`는 제목이라고 하자.
- 본문을 입력하고 제목을 정답으로 사용하면, 모델은 기사 내용을 제목처럼 짧게 표현하는 법을 배운다.
- 한 행의 본문과 제목은 같은 기사를 가리켜야 한다.
- 본문과 정답을 따로 섞으면 서로 다른 사건이 한 쌍으로 묶인다.
- 제목형 요약은 매우 짧은 결과를 목표로 한다. 여러 문장으로 설명하는 요약과 정보의 양이 다르다.
- 빈 본문, 빈 제목, 같은 기사의 중복 행은 학습에 쓰기 전에 구분한다.

---

## 3. 요약에 필요한 의미와 전처리

- HTML 태그와 불필요한 공백은 문장 내용과 분리해 정리할 수 있다.
- 숫자와 단위는 사건의 규모를 나타낸다. `"30명"`과 `"300명"`을 구분할 수 있어야 한다.
- 부정 표현은 사건의 의미를 바꾼다. `"운행한다"`와 `"운행하지 않는다"`는 서로 다른 정답이다.
- 날짜와 이름은 누가 언제 무엇을 했는지 이해하는 데 필요하다.
- Stop word(불용어)는 분석 목적상 제외하는 단어다. 요약문에는 조사·접속어 등 문장을 자연스럽게 연결하는 표현도 필요하다.
- 생성 모델의 정답은 최종적으로 읽고 싶은 문장 형태를 유지한다.

### 같은 전처리를 적용한다는 의미

- 학습과 예측에서 본문을 처리하는 규칙을 맞춘다.
- 본문과 요약문의 역할이 다르므로, 두 열에 적용할 규칙은 각각 정할 수 있다.
- 예를 들어 본문에서는 HTML을 제거하고, 요약문에는 시작·종료 토큰을 추가한다.
- 이 규칙을 일관되게 유지해야 모델이 학습한 입력 형식을 다시 만난다.

---

## 4. 입력·출력 길이 제한의 영향

- 모델에 넣을 최대 토큰 수를 정하면 긴 본문을 자르거나 제외해야 한다.
- 앞부분만 자르는 경우 뒤에 있는 정정 내용이나 결론이 사라질 수 있다.
- 정답 요약문이 잘린 부분의 정보만 설명한다면, 모델은 입력에 없는 내용을 맞히도록 요구받는다.
- 본문 길이와 요약문 길이를 함께 보고, 모델이 받는 본문에 정답의 핵심 내용이 남아 있는지 확인한다.
- 요약문에는 `<bos>`와 `<eos>`를 넣을 자리도 필요하다.
- Truncation(길이 제한)은 정해진 길이 뒤의 토큰을 자르고, Padding(패딩)은 짧은 입력의 뒤에 빈 자리를 채운다.

## 5. 학습·검증·테스트 자료의 역할

| 데이터 구분 | 역할 |
| --- | --- |
| Training data(학습 데이터) | 손실을 계산하고 모델의 가중치를 수정한다. |
| Validation data(검증 데이터) | 학습을 얼마나 할지, 어떤 설정을 선택할지 판단한다. |
| Test data(테스트 데이터) | 설정 선택을 마친 모델의 성능을 확인한다. |

- 같은 기사나 매우 비슷한 기사와 제목이 여러 집합에 나뉘어 있으면, 이미 본 내용을 평가하게 된다.
- 같은 기사에서 파생된 샘플은 같은 집합에 두고 분리한다.
- 새 단어사전과 토크나이저는 학습 데이터로 만든 뒤 검증·테스트에도 그대로 적용한다.
- 학습 손실이 계속 줄어도 검증 손실이 커지기 시작하면 학습 자료에만 맞춰지는 과적합을 의심할 수 있다.
- 최종 요약문도 함께 읽어야 반복, 문장 중단, 핵심 누락을 확인할 수 있다.

## 6. ROUGE와 토큰 겹침 계산

- ROUGE는 생성한 요약과 참고 요약에 공통으로 나타나는 표현을 비교하는 지표다.
- ROUGE-1은 토큰 하나씩의 겹침을, ROUGE-2는 연속된 두 토큰의 겹침을 본다.
- ROUGE-L은 순서를 유지하면서 공통으로 나타나는 가장 긴 토큰열을 사용한다.
- 겹침을 셀 때는 기준이 되는 토큰화 방식도 함께 맞춘다.

### 간단한 ROUGE-1 계산 예시

- 참고 요약: `[시, 버스, 노선, 신설]`
- 생성 요약: `[버스, 노선, 신설]`
- 공통 토큰은 3개다.
- Precision(정밀도)은 `공통 3개 ÷ 생성 3개 = 1.0`이다.
- Recall(재현율)은 `공통 3개 ÷ 참고 4개 = 0.75`다.
- 두 값의 조화평균인 F1은 약 0.857이다.

- 토큰 겹침 평가는 생성한 내용 중 맞게 겹친 비율과 참고 요약에서 포함한 비율을 구분한다. F1은 두 비율의 균형을 하나의 값으로 나타낸다.

**코드 예시**

```python
precision = 3 / 3
recall = 3 / 4
f1 = 2 * precision * recall / (precision + recall)
```

**코드 해설**

- `precision`, `recall`, `f1`은 계산 결과에 붙인 변수 이름이다. `/`로 비율을 구하고, 앞에서 구한 두 비율로 F1을 계산한다.
- 이 예시에서는 정밀도 1, 재현율 0.75, F1 약 0.857이다. 생성한 토큰 세 개는 모두 겹치지만, 정답의 네 토큰 중 한 개는 빠진 경우다.

- 이 예시는 모두 한 번씩 나온 토큰으로 계산했다. 실제 겹침 계산에서는 반복 횟수도 반영한다.
- 같은 뜻을 다른 표현으로 쓴 요약은 토큰 겹침이 작을 수 있으므로, 의미와 사실 관계를 읽는 평가를 함께 둔다.

## 7. 요약의 핵심 내용과 사실 관계 확인

- 원문: `"시는 예산 부족으로 다음 달 버스 증편을 취소했다."`
- 요약 A: `"시는 다음 달 버스를 증편한다."`
- 요약 B: `"예산 부족으로 다음 달 버스 증편이 취소됐다."`

- A는 원문과 단어가 많이 겹치지만, 취소된 사건을 시행하는 것으로 바꾸었다.
- B는 원문에 있는 이유와 결론을 함께 전달한다.
- **주체 → 행동 → 대상 → 시간 → 수량 → 부정·취소 여부**를 순서대로 확인하면 이런 차이를 찾기 쉽다.
- 그다음 핵심 내용의 누락, 불필요한 반복, 문장의 자연스러움을 본다.
- 추출적 요약도 문장 사이의 연결이 끊기거나 대명사가 무엇을 가리키는지 불분명해질 수 있어, 결과 전체를 읽는다.

## 8. 데이터에서 요약 품질까지의 흐름

1. 본문과 정답이 같은 내용을 가리키도록 묶는다.
2. 핵심 정보를 보존하며 텍스트를 정리한다.
3. 중복 기사와 데이터 분할을 확인한다.
4. 길이를 제한하고 토큰 번호로 바꾼다.
5. 다음 요약 토큰을 맞히도록 모델을 학습한다.
6. 검증 결과로 설정을 선택한다.
7. 테스트에서 지표와 실제 문장의 의미를 함께 평가한다.

- 요약 품질의 원인을 찾을 때도 이 순서가 도움이 된다.
- 입력에 핵심 정보가 남아 있는지 확인한 뒤, 모델이 그 정보를 제대로 선택하고 표현했는지 살펴본다.
