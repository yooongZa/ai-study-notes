## 1. 문장의 순서를 처리하는 모델이 필요한 이유

- `"개가 사람을 물었다"`와 `"사람이 개를 물었다"`는 비슷한 단어를 사용하지만 의미가 다르다.
- 단어의 개수만 세면 누가 누구에게 무엇을 했는지 구분하기 어렵다.
- 문장 길이도 입력마다 달라진다. 앞에서 읽은 내용을 반영하며 다음 단어를 처리할 방법이 필요하다.
- RNN(순환 신경망)은 **현재 토큰과 이전 상태를 함께 사용해 새로운 상태를 계산한다.**

---

## 2. RNN의 은닉 상태와 순차 계산

- Hidden state(은닉 상태)는 지금까지 읽은 내용을 나타내는 벡터다.
- 첫 토큰을 읽어 첫 상태를 만들고, 둘째 토큰과 첫 상태로 둘째 상태를 만든다.
- 같은 계산과 같은 가중치를 모든 위치에 반복해서 사용한다.

$$
h_t=\tanh(W_xx_t+W_hh_{t-1}+b)
$$

- `x_t`는 현재 위치의 입력 벡터, `h_{t-1}`은 이전 상태, `h_t`는 새 상태다.
- `W_x`는 현재 입력을 변환하는 가중치이고 `W_h`는 이전 상태를 변환하는 가중치다.
- `b`는 편향, `tanh`는 값을 −1과 1 사이로 바꾸는 활성 함수다.
- 문장 길이가 늘어나면 같은 계산을 더 반복한다. 상태 벡터의 길이는 정해진 크기를 유지한다.
- 뒤쪽의 손실에서 앞쪽 계산까지 미분할 때 작은 값이 반복해서 곱해지면, 앞부분의 가중치까지 전달되는 기울기가 작아질 수 있다.
- 이를 Vanishing gradient(기울기 소실)라고 한다. 긴 문맥을 학습하기 어려워지는 원인 중 하나다.

## 3. LSTM·GRU의 정보 보존과 갱신

- LSTM은 상태를 갱신할 때 어떤 정보를 유지하고, 새로 넣고, 출력할지 조절한다.
- Cell state(셀 상태)인 `c`는 여러 위치에 걸쳐 전달할 정보를 담는다.
- Hidden state(은닉 상태)인 `h`는 현재 위치에서 내보내는 정보를 담는다.
- Gate(게이트)는 보통 0과 1 사이의 값을 계산해 정보의 각 성분을 얼마나 통과시킬지 정한다.
- 0에 가까우면 적게 반영하고, 1에 가까우면 많이 반영한다.

| LSTM의 조절 부분 | 역할 |
| --- | --- |
| Forget gate(망각 게이트) | 이전 셀 상태에서 어느 정보를 유지할지 정한다. |
| Input gate(입력 게이트) | 새로 계산한 후보 정보를 얼마나 추가할지 정한다. |
| Output gate(출력 게이트) | 갱신한 셀 상태에서 어느 정보를 은닉 상태로 내보낼지 정한다. |

- 이런 조절을 통해 중요한 정보가 여러 위치를 거쳐 전달될 수 있다.
- GRU는 갱신·리셋 게이트를 사용하고, 별도의 셀 상태 없이 은닉 상태를 갱신한다.
- PyTorch의 `LSTM`은 `h`와 `c`를 반환하고, `GRU`는 `h`를 반환한다.

## 4. PyTorch LSTM의 입력과 반환값

### torch.nn 모듈의 LSTM 클래스의 활용

- LSTM은 이전 위치에서 전달된 상태를 다음 토큰 계산에 사용한다. 모든 위치의 출력과 마지막 상태를 따로 받으면 문장 전체의 표현과 최종 요약 상태를 각각 활용할 수 있다.

**코드 예시**

```python
import torch
from torch import nn

x = torch.zeros(2, 3, 4)
lstm = nn.LSTM(input_size=4, hidden_size=5, batch_first=True)
outputs, (h, c) = lstm(x)
```

**코드 해설**

- `nn.LSTM(...)`은 레이어 객체를 만들고, `lstm(x)`는 입력의 토큰을 순서대로 처리한다. 첫 토큰에서 얻은 상태를 둘째 토큰 계산에 사용하며 마지막 위치까지 이어 간다.
- `outputs, (h, c) = ...`는 반환된 묶음을 세 변수로 나눠 받는 문법이다. `outputs`에는 모든 위치의 결과, `h`와 `c`에는 마지막 상태가 들어간다.

- `x`는 문장 2개, 문장마다 토큰 3개, 토큰 벡터 차원 4를 가진 예시다.
- `input_size=4`는 토큰 하나의 벡터 길이, `hidden_size=5`는 상태 벡터 길이다.
- `batch_first=True`이면 입력과 `outputs`의 축 순서는 `(배치, 길이, 차원)`이다.
- `outputs`의 형태는 `(2, 3, 5)`다. 각 문장의 모든 위치에 대한 은닉 상태가 담긴다.
- `h`와 `c`의 형태는 각각 `(1, 2, 5)`다. 기본 설정인 단방향·1개 레이어의 마지막 상태다.
- `h`와 `c`의 첫 축은 레이어와 방향을 구분한다. `batch_first`를 켜도 이 축 순서는 유지된다.
- 이 호출은 순서에 따른 계산을 수행한다. 가중치 갱신은 손실 계산과 역전파 이후에 일어난다.

## 5. Seq2seq의 인코더와 디코더

- 번역에서는 한국어 입력과 영어 출력의 길이가 다를 수 있다.
- Encoder(인코더)는 입력 문장을 순서대로 읽어 정보를 만든다.
- Decoder(디코더)는 전달받은 정보와 이전 출력 토큰을 바탕으로 새 토큰을 만든다.
- 기본적인 LSTM Seq2seq는 인코더의 마지막 `h, c`를 디코더의 초기 상태로 전달한다.
- 디코더의 상태를 출력층에 넣으면 다음 토큰마다 점수가 나온다.
- `<bos>`부터 생성해 `<eos>`에서 끝내면 길이가 다른 문장을 만들 수 있다.
- 요약에서도 같은 구조를 사용한다. 입력은 긴 본문이고 출력은 짧은 요약문이다.

## 6. Attention의 참고 비율과 문맥 벡터

- 입력이 길어질수록 마지막 상태만으로 모든 세부 내용을 전달하기가 어렵다.
- Attention은 인코더의 **모든 위치의 출력**을 남겨 두고, 현재 출력에 필요한 정보를 계산한다.

1. 현재 디코더 상태와 인코더의 각 위치를 비교해 점수를 만든다.
2. Softmax(소프트맥스)로 점수를 합이 1인 가중치로 바꾼다.
3. 각 인코더 벡터에 해당 가중치를 곱한다.
4. 곱한 벡터들을 더해 Context vector(문맥 벡터)를 만든다.
5. 이 문맥 벡터와 디코더 정보를 함께 사용해 다음 토큰을 예측한다.

- 출력 위치가 바뀌면 비교하는 디코더 상태가 바뀌므로, 참고 비율과 문맥 벡터도 달라진다.
- 패딩 위치의 점수는 Softmax 전에 가려서 실제 입력 토큰에만 가중치를 배분한다.

### torch 모듈의 softmax 함수의 활용

- Attention은 참고할 입력마다 비율을 정하고 그 비율로 벡터를 섞는 계산이다. 점수를 합이 1인 비율로 바꾼 뒤 가중합을 구하면 현재 출력에 필요한 문맥 벡터가 된다.

**코드 예시**

```python
scores = torch.tensor([0.0, 1.0])
weights = torch.softmax(scores, dim=-1)

encoder_vectors = torch.tensor([[1.0, 0.0], [0.0, 2.0]])
context = weights @ encoder_vectors
```

**코드 해설**

- `softmax()`가 점수 둘을 합계 1인 비율로 바꾼다. 그 비율을 입력 벡터 각각에 곱한 뒤 더하면 현재 출력에 사용할 `context`가 된다.

- 예시에서는 두 입력 위치의 점수가 0과 1이라고 정했다.
- `weights`는 약 `[0.269, 0.731]`이다. 둘째 위치에 더 큰 비율을 준다.
- `dim=-1`은 마지막 축을 따라 비율을 계산한다는 뜻이다.
- `@`는 행렬 곱 문법이다. 여기서는 각 벡터에 가중치를 곱해 더한다.
- `context`는 약 `[0.269, 1.462]`다. 두 입력 벡터를 현재 출력에 필요한 비율로 섞은 결과다.

## 7. Attention 점수의 계산 방식

- **Bahdanau의 가산형 Attention**은 디코더 상태와 인코더 출력을 각각 변환해 더한 뒤, 작은 신경망으로 점수를 구한다.
- **Luong의 내적 기반 Attention**은 두 벡터의 내적이나 가중치 변환을 거친 내적으로 점수를 구한다.
- 두 방식 모두 **점수 → Softmax 가중치 → 입력 벡터의 가중합**을 사용한다.
- 어떤 벡터를 비교하고 점수를 어떻게 계산하는지가 다르다.
- Attention 가중치를 표로 그리면, 각 출력 토큰을 계산할 때 어느 입력 위치를 많이 참고했는지 살펴볼 수 있다.

## 8. RNN과 Transformer의 정보 전달 방식

- RNN 기반 모델은 현재 상태를 계산하려면 이전 상태가 먼저 필요하다.
- Attention을 붙여도 RNN의 순서대로 계산하는 구조는 남아 있다.
- Transformer는 Attention으로 토큰 사이의 관계를 직접 계산한다.
- **순서대로 상태 갱신 → 입력 전체를 참고하는 Attention → Attention 중심의 문맥 계산**으로 발전하는 흐름을 잡으면 다음 구조를 이해하기 쉽다.
