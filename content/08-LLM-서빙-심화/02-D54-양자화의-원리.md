title: "D54. 양자화의 원리"
---

사용하려는 모델이 GPU 메모리에 들어가지 않을 때, 가중치를 더 적은 공간에 저장하는 방법을 사용할 수 있습니다. 가중치가 70억 개인 모델을 FP16으로 저장하면 가중치에 약 14GB가 필요합니다. 이를 4비트로 표현하면 가중치 값 자체의 저장량은 약 3.5GB로 줄어듭니다.

이렇게 숫자를 더 적은 비트로 표현하는 것이 **Quantization(양자화)**입니다. 여기서는 가중치를 어떻게 압축하는지, 그 과정에서 왜 오차가 생기는지, 압축한 모델의 답변 품질을 어떻게 확인하는지 배웁니다.

## 학습 목표와 흐름

| 배울 내용 | 이해할 내용 |
|---|---|
| 수의 표현 | FP16·BF16·정수 형식의 범위와 정밀도 |
| 스케일과 영점 | 실숫값을 작은 정수 코드로 저장하고 복원하는 방법 |
| 이상치와 그룹 | 큰 값 하나가 다른 값의 오차에 영향을 주는 이유 |
| NF4와 이중 양자화 | 대표값의 배치와 부가 정보 압축 |
| QLoRA | 양자화한 모델을 적은 학습 메모리로 조정하는 방법 |
| 품질 평가 | 가중치 변화가 실제 답변과 자원 사용에 미친 영향 |

## 자습

### 1. 양자화로 줄어드는 것과 생기는 오차

모델의 가중치는 많은 숫자로 이루어져 있습니다. 값 하나를 저장하는 비트 수가 줄어들면 전체 가중치의 저장량도 줄어듭니다. 저장할 수 있는 숫자의 종류도 함께 줄어들기 때문에, 원래 숫자를 가까운 대표값으로 바꾸어야 합니다.

예를 들어 소수 첫째 자리까지만 남긴다면 1.23과 1.24를 모두 1.2로 표현합니다. 원래 값과의 차이가 Quantization error(양자화 오차)입니다. 모델에서도 이 차이가 계산 결과와 답변에 영향을 주므로, 메모리 절약과 함께 답변의 변화를 확인합니다.

| 가중치 형식 | 값 하나의 저장량 | 가중치 70억 개의 저장량 |
|---|---:|---:|
| FP32 | 4바이트 | 28GB |
| FP16·BF16 | 2바이트 | 14GB |
| INT8 | 1바이트 | 7GB |
| 4비트 코드 | 0.5바이트 | 3.5GB |

표는 가중치 값에 필요한 공간입니다. 실제로 실행할 때는 숫자를 복원할 정보, 높은 정밀도로 유지한 계층, KV 캐시와 중간 계산값도 메모리를 사용합니다. 각 항목을 합쳐 모델 실행에 필요한 공간을 계산합니다.

### 2. 숫자의 범위와 정밀도, 저장과 계산의 차이

양자화 방식을 고르려면 먼저 숫자 형식이 무엇을 바꾸는지 알아야 합니다. 숫자를 표현할 때는 **얼마나 큰 값까지 담을 수 있는지**와 **가까운 두 값을 얼마나 세밀하게 구분하는지**가 중요합니다.

Floating point(부동소수점)는 부호·지수·가수부로 숫자를 표현합니다. 지수에 비트를 많이 쓰면 표현 범위가 넓어지고, 가수부에 많이 쓰면 가까운 값을 세밀하게 구분할 수 있습니다.

| 형식 | 부호·지수·가수부 비트 | 특징 |
|---|---|---|
| FP32 | 1·8·23 | 넓은 범위와 높은 정밀도 |
| FP16 | 1·5·10 | BF16보다 세밀한 유효숫자, 최대 유한 양수 65,504 |
| BF16 | 1·8·7 | FP32와 비슷한 표현 범위 |

예를 들어 70,000은 FP16의 범위를 넘습니다. BF16에는 담을 수 있지만 가까운 표현값인 70,144로 반올림됩니다. 이처럼 범위 안에 들어오는 것과 원래 값을 정확히 표현하는 것은 각각 확인할 항목입니다.

양자화 모델을 읽을 때는 **저장 형식과 계산 형식**도 구분합니다. 가중치는 4비트 코드로 저장하고, 행렬곱에 필요한 값을 FP16으로 복원해 계산할 수 있습니다. W4A16은 가중치에 4비트, Activation(활성값)에 16비트를 사용한다는 뜻입니다. 활성값은 모델이 입력을 처리하며 만드는 중간값이며, 선형 계층에서는 그 층에 들어오는 특징값이 해당합니다.

### 3. 스케일과 영점으로 숫자를 저장하고 복원하는 방법

실숫값을 정수 코드로 저장하려면 정수 한 칸이 원래 값의 얼마에 해당하는지 정해야 합니다. 이 간격이 **Scale(스케일)**입니다. 복원할 때는 저장한 코드에 스케일을 적용해 원래 값에 가까운 숫자를 얻습니다.

가중치가 −5.4부터 5.4 사이에 있고, −127부터 127까지의 정수 코드를 사용한다면 한 칸의 간격은 $5.4/127\approx0.04252$입니다. 가중치 1.2를 이 간격으로 나누면 약 28.222가 되므로 정수 28을 저장합니다. 복원하면 $28\times0.04252\approx1.19055$가 됩니다.

0을 중심으로 양쪽에 같은 범위를 배정하는 이 방식이 Symmetric quantization(대칭 양자화)입니다.

$$s=\frac{\max_i|x_i|}{127},\qquad q_i=\operatorname{round}(x_i/s),\qquad \hat x_i=q_i s$$

$x$는 원래 값, $q$는 저장할 정수 코드, $\hat x$는 복원한 값입니다. 코드를 근삿값으로 되돌리는 과정을 Dequantization(역양자화)이라고 합니다. 반올림하면서 사라진 차이는 복원한 뒤에도 오차로 남습니다.

값이 0부터 10처럼 한쪽 구간에 모여 있다면 그 구간에 정수 코드를 배분할 수 있습니다. **Asymmetric quantization(비대칭 양자화)**은 스케일과 함께 Zero-point(영점)를 사용합니다. 영점은 원래 값 0에 대응하는 정수 코드입니다.

0부터 10을 −128부터 127에 대응시키면 스케일은 $10/255$, 영점은 −128입니다. 원래 값 2를 코드 −77로 저장한 뒤, $(-77-(-128))\times10/255=2$로 복원할 수 있습니다.

$$q=\operatorname{clip}(\operatorname{round}(x/s)+z,q_{min},q_{max}),\qquad \hat x=(q-z)s$$

$z$가 영점이며, `clip`은 계산한 코드가 사용할 정수 범위를 벗어나면 경계값으로 제한한다는 뜻입니다. 스케일은 $s=(x_{max}-x_{min})/(q_{max}-q_{min})$으로, 영점은 $z=\operatorname{round}(q_{min}-x_{min}/s)$로 구합니다.

### 4. 이상치가 있는 가중치를 그룹으로 나누는 이유

스케일을 정할 때는 몇 개의 값이 같은 스케일을 공유할지도 선택합니다. 대부분의 가중치가 작은데 유난히 큰 값 하나가 섞여 있다면, 전체를 담기 위해 간격이 넓어집니다. 이때 작은 값 사이의 차이를 표현하기 어려워집니다.

예를 들어 최대 절댓값이 5.4일 때 INT8 간격은 약 0.0425입니다. 같은 묶음에 60이라는 값이 들어오면 간격은 약 0.4724로 커집니다. 0.1과 0.2 같은 작은 값이 같은 코드로 묶일 수 있습니다. 이렇게 다른 값보다 크게 튀는 값을 Outlier(이상치)라고 합니다.

**값들을 작은 묶음으로 나누고 각각 스케일을 정하면, 한 묶음의 큰 값이 다른 묶음의 간격까지 넓히는 일을 줄일 수 있습니다.**

| 방식 | 스케일을 공유하는 범위 |
|---|---|
| Per-tensor(텐서별) | 텐서 전체 |
| Per-channel(채널별) | 선택한 채널 하나 |
| Per-group·block(그룹·블록별) | 일정 개수의 값 |

그룹을 작게 나누면 각 부분의 값에 맞춰 스케일을 정하기 쉽습니다. 그만큼 저장할 스케일 수도 늘어납니다. 가중치 64개마다 FP32 스케일 하나를 저장하면 스케일 비용은 가중치당 $32/64=0.5$비트입니다.

활성값에서도 큰 값이 나타납니다. LLM.int8()은 이런 활성값이 나타나는 특징 차원의 계산을 FP16 경로로 처리하고, 나머지 특징은 INT8 경로로 처리한 뒤 결과를 합칩니다. 큰 값이 계산에 미치는 영향을 높은 정밀도로 다루면서 나머지 부분을 저정밀도로 계산하는 방식입니다.

### 5. NF4의 대표값과 이중 양자화

4비트에는 16개 코드를 담을 수 있습니다. 같은 16개를 사용하더라도 어떤 숫자를 대표값으로 정하느냐에 따라 오차가 달라집니다. 값이 많이 모여 있는 구간에 대표값을 촘촘히 두면 그 구간을 더 세밀하게 표현할 수 있습니다.

**NF4(NormalFloat 4-bit, 정규분포 기반 4비트 형식)**는 정규분포를 기준으로 0 근처에 대표값을 촘촘히 배치합니다. Quantile(분위수)은 누적확률의 경계값입니다. 정규분포의 확률 면적을 비슷하게 나누면 값이 많이 모인 중심부의 경계가 촘촘해집니다. NF4는 이 원리를 이용해 −1부터 1 사이의 대표값을 정하고 정확한 0도 포함합니다.

가중치 0.08을 저장하고, 그 블록의 최대 절댓값이 0.5인 경우를 따라가면 다음과 같습니다.

1. 블록 스케일로 나누어 $0.08/0.5=0.16$으로 맞춥니다.
2. 가까운 NF4 대표값인 약 0.1609302를 고릅니다.
3. 그 대표값의 번호를 4비트 코드로 저장합니다.
4. 복원할 때 대표값에 0.5를 곱해 약 0.0804651을 얻습니다.

| 형식 | 16개 코드가 나타내는 값 |
|---|---|
| INT4 | 스케일·영점으로 정한 균등 간격의 값 |
| NF4 | 정규분포를 기준으로 배치한 불균등 간격의 대표값 |
| FP4 | 지수·가수부 구성에 따라 정해지는 부동소수점 값 |

FP4의 E2M1은 부호 1비트·지수 2비트·가수 1비트 구성입니다. NVFP4처럼 이 표현에 블록 스케일을 결합한 형식도 있습니다. 형식 이름을 읽을 때는 대표값의 배치와 스케일의 저장 방식을 함께 확인합니다.

가중치를 4비트로 줄이고 나면 스케일이 차지하는 비중도 커집니다. 앞의 64개 단위 예에서는 가중치 4비트에 스케일 0.5비트가 더해져 원소당 평균 4.5비트를 사용합니다.

**Double quantization(이중 양자화)**은 이 스케일을 다시 압축합니다. 스케일을 8비트로 저장하고 스케일 256개마다 FP32 보조 스케일을 둔다면, 스케일 비용은 원래 가중치당 약 0.127비트가 됩니다. 복원할 때는 보조 스케일로 블록 스케일을 구하고, 그 블록 스케일로 가중치를 복원합니다.

### 6. 양자화한 모델을 학습하는 QLoRA

모델을 작은 GPU에 올린 다음 특정 업무에 맞춰 학습시키고 싶을 수 있습니다. 학습에는 가중치 외에도 기울기와 Optimizer(최적화 알고리즘)의 상태가 필요하므로, 학습할 가중치 수를 줄이는 방법이 도움이 됩니다.

**LoRA(저랭크 적응)**는 기본 가중치를 고정하고 작은 행렬 두 개로 변화량을 학습합니다. 큰 가중치 행렬 전체를 갱신하는 대신, 적은 수의 추가 파라미터로 업무에 맞는 변화를 배웁니다.

**QLoRA는 양자화한 기본 모델에 LoRA를 적용해 학습하는 구성**입니다. NF4는 기본 가중치를 저장하고, 이중 양자화는 스케일의 저장량을 줄이며, LoRA는 새로 학습할 가중치를 구성합니다.

기본 가중치가 $d_{out}\times d_{in}$ 크기라면 LoRA는 $r\times d_{in}$인 $A$와 $d_{out}\times r$인 $B$를 학습합니다. 작은 $r$을 선택하면 추가 파라미터 수는 $r(d_{in}+d_{out})$이 됩니다. 두 행렬의 곱 $BA$가 원래 가중치에 더할 변화량입니다.

$$Y=X(\hat W+\lambda BA)^{\mathsf T}$$

$\hat W$는 계산을 위해 복원한 기본 가중치, $\lambda$는 LoRA 변화량의 배율입니다. 기본 가중치는 고정한 채 $A$와 $B$를 학습합니다.

학습 메모리를 관리할 때는 연산과 상태에 맞춰 자료형을 나누는 Mixed precision(혼합 정밀도)도 사용합니다. FP16의 작은 기울기를 다룰 때 사용하는 Loss scaling(손실 스케일링)은 손실을 키워 역전파하고, 가중치를 갱신하기 전에 그 배율을 되돌립니다. Paged optimizer(페이지 기반 옵티마이저)는 학습 상태를 CPU와 GPU 사이에서 관리해 순간적인 GPU 메모리 증가를 다룹니다.

### 7. 양자화를 적용하는 시점과 대상

이미 학습한 모델을 서비스에 넣으려는 경우와, 양자화 오차를 고려해 모델을 학습하려는 경우는 준비 과정이 다릅니다. 목적에 따라 양자화를 언제 적용하고 어떤 가중치를 학습할지 정합니다.

| 방법 | 적용하는 방식 | 사용하는 상황 |
|---|---|---|
| PTQ(학습 후 양자화) | 학습이 끝난 가중치를 저정밀도로 변환 | 기존 모델의 저장량과 추론 메모리를 줄일 때 |
| QAT(양자화 인지 학습) | 학습 중 양자화의 반올림·범위 제한을 반영 | 가중치가 양자화 오차에 적응하도록 학습할 때 |
| QLoRA | 양자화한 기본 모델 위에서 LoRA 학습 | 제한된 학습 메모리로 업무에 맞게 조정할 때 |

양자화 대상도 정해야 합니다. 학습이 끝난 가중치는 고정되어 있어 미리 분포를 확인할 수 있습니다. 활성값은 입력 문장과 토큰 위치에 따라 바뀌므로, 이를 양자화하려면 실제 입력에서 나타나는 범위를 고려해야 합니다. W4A16 같은 가중치 전용 방식은 활성값을 16비트로 유지하면서 가중치 저장량을 줄입니다.

### 8. 양자화한 모델의 답변 품질을 확인하는 방법

양자화를 마쳤다면 메모리가 얼마나 줄었는지와 답변이 어떻게 달라졌는지를 함께 확인합니다. 가중치의 숫자 차이는 첫 번째 확인 대상이고, 그 차이가 실제 입력을 처리할 때 어떤 출력을 만드는지가 다음 확인 대상입니다.

선형 계층은 입력과 가중치를 곱합니다. 가중치 오차가 0.1일 때 입력이 10이면 출력 차이는 1이고, 입력이 1이면 0.1입니다. 같은 가중치 오차도 실제로 들어오는 입력에 따라 영향이 달라집니다. 여러 층을 거친 뒤에는 다음 토큰 선택과 답변이 달라질 수 있습니다.

| 평가할 내용 | 확인할 값 |
|---|---|
| 계산의 변화 | 가중치·계층 출력의 MSE(평균 제곱 오차) |
| 다음 토큰 예측 | PPL(퍼플렉서티), 기준 모델과의 1순위 토큰 일치율 |
| 실제 답변 | 정답 수, 정오답이 바뀐 문항, 숫자·JSON 등 출력 형식 |
| 자원과 시간 | 로드·생성 중 메모리, 첫 토큰 시간, 생성 속도 |

PPL은 주어진 글의 실제 다음 토큰에 모델이 얼마나 높은 확률을 주는지 나타냅니다. 각 정답 토큰에 0.5의 확률을 준다면 PPL은 2입니다. 같은 글과 토크나이저로 비교할 때 낮은 PPL은 그 글의 정답 토큰을 더 잘 예측했다는 뜻입니다.

$$\mathrm{PPL}=\exp\left(-\frac1N\sum_t\log p(x_t\mid x_{<t})\right)$$

긴 글은 겹치는 구간으로 나누어 앞부분을 문맥으로 제공하고, 새로 채점할 토큰만 집계합니다. 실제 서비스의 품질은 별도로 준비한 질문에 대한 답을 읽고 평가합니다. 정답 수와 함께 맞→틀, 틀→맞 문항을 기록하면 어떤 답변이 달라졌는지 확인할 수 있습니다.

메모리 절약률은 $1-\text{양자화 후 사용량}/\text{기준 사용량}$으로 구합니다. 속도에는 가중치를 읽는 양이 줄어드는 효과와 압축된 값을 복원하는 연산 비용이 함께 반영됩니다. 같은 GPU와 입력·출력 길이에서 측정해 사용할 모델을 정합니다.

## 이해 확인

> [!question]- 양자화하면 저장량이 줄어드는 대신 왜 오차가 생기나요?
> 적은 비트로 표현할 수 있는 값의 종류가 줄어들어, 원래 값을 가까운 대표값으로 바꾸기 때문입니다.

> [!question]- 스케일과 영점은 무엇을 정하나요?
> 스케일은 정수 한 칸이 나타내는 실수 간격을, 영점은 원래 값 0에 해당하는 정수 코드를 정합니다.

> [!question]- 그룹을 작게 나누면 무엇이 달라지나요?
> 각 부분의 값에 맞는 스케일을 정하기 쉬워지고, 저장해야 할 스케일 수가 늘어납니다.

> [!question]- NF4·이중 양자화·LoRA는 각각 무엇을 담당하나요?
> 기본 가중치의 대표값 표현, 스케일 압축, 학습할 작은 추가 행렬을 담당합니다.

> [!question]- 양자화 전후의 정답 수가 같다면 다음에 무엇을 읽어야 하나요?
> 정오답이 바뀐 문항과 실제 답변을 읽습니다. 맞힌 질문의 구성이 어떻게 달라졌는지 확인할 수 있습니다.
