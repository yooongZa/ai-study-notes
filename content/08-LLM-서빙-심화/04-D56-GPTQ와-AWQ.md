title: "D56. GPTQ와 AWQ"
---

LLM의 가중치를 4비트로 줄이면 작은 GPU에 모델을 올리기 쉬워집니다. 그 과정에서 가중치가 원래 값과 달라지므로, 모델이 계산하는 값과 답변도 바뀔 수 있습니다. 이 변화를 줄이기 위해 실제 입력을 사용해 양자화 방법을 조정합니다.

여기서는 **GPTQ와 AWQ가 양자화 오차를 줄이는 원리**를 배웁니다. 이어서 양자화한 모델을 파일로 저장하고, 사용할 GPU에서 답변 품질·속도·메모리를 비교하는 방법까지 연결합니다.

## 학습 목표와 흐름

| 배울 내용 | 이해할 내용 |
|---|---|
| 사전 양자화 | 모델을 미리 양자화해 파일로 준비하는 이유 |
| 보정 데이터와 활성값 | 실제 입력을 넣어 무엇을 관찰하고 어디에 사용하는지 |
| GPTQ | 양자화하며 생긴 오차를 남은 가중치로 보상하는 방법 |
| AWQ | 중요한 입력 채널의 가중치를 더 정확하게 표현하는 방법 |
| 저장 형식과 커널 | 양자화 파일이 GPU에서 계산되는 과정 |
| 비교와 선택 | 실제 서비스 조건에서 사용할 모델을 고르는 기준 |

## 자습

### 1. 모델을 미리 양자화해 저장하는 이유

여러 서버에 같은 모델을 배포하거나, 인터넷 연결이 제한된 환경에 모델을 가져가려면 사용할 모델 파일을 미리 준비해야 합니다. 이때 양자화한 가중치를 파일로 저장해 두면 압축된 파일을 옮겨 같은 설정으로 다시 로드할 수 있습니다.

양자화는 적용하는 시점에 따라 다음처럼 구성할 수 있습니다.

| 방식 | 진행 과정 | 사용하는 상황 |
|---|---|---|
| 로드 시 양자화 | 원본 가중치를 읽으면서 저정밀도로 변환 | 모델의 메모리 사용량과 답변을 빠르게 시험할 때 |
| 사전 양자화 | 가중치를 미리 변환해 저장한 뒤 그 파일을 로드 | 반복 배포할 모델 파일을 준비할 때 |

bitsandbytes의 NF4 로드는 로드 시 양자화의 한 예입니다. GPTQ와 AWQ는 보정 입력을 이용해 가중치를 양자화하고, 그 결과를 파일로 준비하는 데 사용합니다. 두 방법은 이미 학습된 모델에 적용하는 PTQ(Post-training quantization, 학습 후 양자화)에 속합니다.

직접 양자화하려면 원본 모델을 처리할 메모리와 작업 시간이 필요합니다. 이미 만들어진 양자화 모델을 사용할 때는 원본 모델 버전, 양자화 설정, 사용할 실행 도구와의 호환성을 확인합니다.

### 2. 양자화 전에 실제 입력과 활성값을 살피는 이유

모델을 양자화할 때는 답변에 큰 영향을 주는 오차를 줄이는 것이 중요합니다. 어떤 가중치의 변화가 중요한지 알려면 그 가중치에 실제로 어떤 값이 곱해지는지 살펴봐야 합니다.

가중치가 0.50에서 0.49로 바뀌었다면 차이는 0.01입니다. 여기에 입력 1이 곱해지면 출력 차이는 0.01이고, 입력 100이 곱해지면 출력 차이는 1입니다. **같은 가중치 변화도 큰 입력과 곱해지면 출력에 더 크게 반영됩니다.**

그래서 양자화를 시작하기 전에 실제로 사용할 문장과 비슷한 입력을 모델에 통과시킵니다. 이 대표 문장들이 Calibration data(보정 데이터)입니다. 한국어 사내 문서를 다룰 모델이라면 실제 업무의 언어·문서 종류·길이를 반영한 문장을 준비합니다.

문장이 모델의 여러 층을 지나면서 만들어지는 값을 Activation(활성값)이라고 합니다. 어떤 선형 계층에 4,096개 숫자로 된 벡터가 들어온다면 입력 특징이 4,096개인 것입니다. 그 벡터의 한 좌표를 Input channel(입력 채널)이라고 부릅니다.

보정 문장을 통과시키면 채널마다 어떤 크기의 값이 나타나는지, 채널들의 값이 어떻게 함께 변하는지 관찰할 수 있습니다. GPTQ는 이 정보를 오차 보상에 사용하고, AWQ는 중요한 채널과 그 채널에 적용할 배율을 정하는 데 사용합니다.

이 관찰은 보정 입력을 모델에 통과시키는 Forward pass(순전파)로 수행합니다. 질문의 정답 라벨 없이도 계층별 입력 통계를 구할 수 있습니다. 완성된 모델의 답변을 채점할 Evaluation data(평가 데이터)는 별도로 준비합니다.

| 자료 | 사용하는 시점 | 목적 |
|---|---|---|
| 보정 데이터 | 양자화할 때 | 입력 통계를 얻고 양자화 오차를 줄임 |
| 평가 데이터 | 양자화한 모델을 비교할 때 | 새 질문의 답변 품질과 실행 성능 확인 |

### 3. GPTQ가 양자화 오차를 보상하는 방법

여러 가중치를 각각 가까운 값으로 반올림하면, 각 가중치에서 생긴 오차가 출력에 더해집니다. GPTQ는 한 가중치를 양자화한 뒤 나머지 가중치를 조정해 이 출력 차이를 줄입니다.

계산에 들어가는 두 항의 합이 1.2인데 첫 항을 양자화하면서 0.4가 늘었다면, 다른 항을 줄여 합의 변화를 줄일 수 있습니다. GPTQ도 이와 같이 **이미 양자화한 부분에서 생긴 오차를 아직 처리하지 않은 가중치에 반영**합니다. 실제로는 여러 보정 입력에서 나온 출력을 함께 고려합니다.

과정은 다음과 같습니다.

1. 보정 입력으로 원래 계층의 출력을 구합니다.
2. 가중치 일부를 낮은 비트로 양자화합니다.
3. 그 변화로 생긴 오차를 줄이도록 아직 양자화하지 않은 가중치를 조정합니다.
4. 다음 가중치를 처리하며 같은 과정을 이어갑니다.

어느 방향으로 조정할지는 보정 입력의 관계를 이용해 계산합니다. 두 입력 채널이 자주 함께 변한다면, 한 가중치의 변화로 생긴 출력 차이를 다른 가중치의 조정으로 줄일 수 있습니다.

입력이 $X$, 원래 가중치가 $W$, 양자화한 가중치가 $\hat W$라면 줄이려는 차이는 다음과 같습니다.

$$\min_{\hat W}\;\|XW^{\mathsf T}-X\hat W^{\mathsf T}\|_F^2$$

식 안의 두 항은 각각 원래 출력과 양자화한 출력입니다. $\|\cdot\|_F^2$는 그 차이의 원소들을 제곱해 더한 값입니다. 보정 입력 전체에서 출력이 얼마나 달라졌는지 하나의 수로 나타냅니다.

GPTQ는 $X^{\mathsf T}X$ 형태의 입력 통계로 Hessian(헤시안)에 해당하는 2차 정보를 구성해 보상량을 계산합니다. 이 정보는 어떤 가중치를 얼마나 바꿨을 때 출력 오차가 어떻게 달라지는지 나타냅니다. 보정 통계로 계층별 조정을 계산하므로, 정답을 두고 역전파하는 추가 학습 없이 적용할 수 있습니다. [GPTQ 논문](https://arxiv.org/abs/2210.17323)

### 4. AWQ가 활성값을 이용해 중요한 채널을 보호하는 방법

AWQ를 적용할 때는 가중치를 4비트로 바꾸기 전에 입력 채널별 활성값을 관찰합니다. 앞에서 본 것처럼 큰 입력과 곱해지는 가중치의 오차는 출력에 크게 반영될 수 있습니다. AWQ는 이 정보를 이용해 중요한 채널의 가중치가 양자화 후에도 더 정확하게 표현되도록 합니다.

**AWQ(Activation-aware Weight Quantization, 활성값을 고려한 가중치 양자화)**는 채널별로 가중치에 배율을 적용합니다. 가중치를 키운 만큼 입력은 나누어, 양자화 전 계산 결과를 유지합니다.

예를 들어 입력 3과 가중치 2.4의 곱은 7.2입니다. 가중치를 10배인 24로 키우고 입력을 10으로 나누어 0.3으로 바꾸면 곱은 여전히 7.2입니다. 이렇게 원래 계산을 유지한 상태에서, 배율을 적용한 가중치를 양자화합니다.

채널별 배율을 대각행렬 $D$로 나타내면 다음 관계가 됩니다.

$$XW^{\mathsf T}=(XD^{-1})(WD)^{\mathsf T}$$

$WD$는 가중치의 각 입력 채널에 배율을 곱한 값이고, $XD^{-1}$은 입력 채널을 같은 배율로 나눈 값입니다. 두 배율이 곱에서 상쇄되어 양자화 전 출력은 같습니다.

중요한 채널의 가중치를 키우면 양자화 후 그 채널의 상대적인 오차를 줄일 수 있습니다. 한편 같은 그룹의 값은 스케일을 공유하므로, 채널을 키우면 그룹 전체의 양자화 간격도 달라집니다. AWQ는 **여러 배율 후보를 적용한 뒤 보정 입력의 출력 오차를 비교해 배율을 고릅니다.**

입력에 적용할 역배율은 연결된 앞 계층의 계산에 합칠 수 있습니다. Q·K·V처럼 같은 입력을 사용하는 계층들은 그 연결 관계에 맞춰 배율을 함께 반영합니다. [AWQ 논문](https://arxiv.org/abs/2306.00978)

| 비교 | GPTQ | AWQ |
|---|---|---|
| 주로 하는 조정 | 양자화한 부분의 오차를 남은 가중치에 반영 | 채널별 가중치와 입력에 서로 역인 배율 적용 |
| 보정 입력의 용도 | 오차를 보상할 방향과 양 계산 | 중요한 채널과 배율 선택 |
| 목표 | 계층 출력의 변화 감소 | 중요한 채널의 양자화 오차 감소 |

### 5. 비트 수와 그룹 크기 등 양자화 설정의 의미

GPTQ와 AWQ의 원리를 이해했다면 이제 어떤 설정으로 모델을 만들지 정할 수 있습니다. 설정은 압축한 값의 종류, 스케일을 공유하는 범위, 가중치를 처리하는 순서를 결정합니다.

| 설정 | 뜻 | 예 |
|---|---|---|
| `bits` | 가중치 코드의 비트 수 | 4비트는 16개 코드 사용 |
| `group_size` | 하나의 스케일을 공유하는 가중치 수 | 128이면 가중치 128개가 한 그룹 |
| Scale(스케일) | 코드 간격과 원래 값의 관계 | 그룹마다 저장 |
| Zero-point(영점) | 원래 값 0에 대응하는 코드 | 비대칭 양자화에서 사용 |
| `sym` | 대칭 양자화 사용 여부 | 값의 범위를 0 중심으로 배치할지 선택 |
| `desc_act` | GPTQ에서 활성값 기준의 처리 순서 사용 여부 | 큰 활성값에 해당하는 열을 먼저 처리 |

그룹을 작게 만들면 부분마다 값의 범위에 맞는 스케일을 정하기 쉽고, 저장할 스케일은 늘어납니다. 사용할 GPU 커널이 지원하는 비트 수와 그룹 크기도 함께 확인합니다.

NF4는 16개 대표값을 어떻게 배치할지 정한 형식입니다. GPTQ와 AWQ는 실제 입력을 이용해 가중치를 어떻게 조정하며 양자화할지 정하는 방법입니다. 모델을 비교할 때는 각각의 저장 형식과 실제 양자화 설정을 기록합니다.

### 6. 저장한 양자화 모델이 GPU에서 실행되는 과정

양자화가 끝난 모델을 다른 서버에서 사용하려면 압축한 가중치와 복원 정보가 함께 있어야 합니다. 모델 폴더에는 가중치, 스케일·영점 같은 양자화 정보, 모델 구조 설정, 토크나이저와 대화 형식을 저장합니다.

파일을 로드한 뒤 실제 계산을 맡는 것은 GPU 커널입니다. 이 과정에서 각 요소의 역할을 나누면 파일을 만들었는데 실행이 느린 이유도 찾기 쉽습니다.

| 요소 | 역할 | 예 |
|---|---|---|
| Algorithm(알고리즘) | 양자화할 값을 결정 | GPTQ·AWQ |
| Format(저장 형식) | 값·스케일·설정을 파일에 배치 | 양자화 도구가 저장하는 파일 규칙 |
| Kernel(연산 커널) | 압축된 표현을 이용해 GPU 계산 | Marlin 계열 커널 |
| Runtime(실행 도구) | 모델 로드와 생성 실행을 연결 | Transformers·vLLM |

실행 도구는 모델 형식과 GPU 조건에 맞는 커널을 사용합니다. 선택한 고속 커널을 사용할 수 없어 다른 구현으로 계산하는 것을 Fallback(대체 경로 사용)이라고 합니다. 이 경우 실제 선택된 경로를 실행 로그에서 확인합니다.

양자화로 가중치를 읽는 양은 줄어들지만, 실행 시간에는 압축된 값을 처리하는 방식도 영향을 줍니다. 그래서 배포할 GPU에서 **저장한 파일을 다시 로드하고 실제 생성 시간을 측정**합니다. 로드 직후 메모리와 생성 중 최대 메모리도 함께 확인합니다.

모델 카드에는 원본 모델 이름·버전, 라이선스 정보, 양자화 설정, 보정 데이터의 특성, 평가 결과와 실행 환경을 기록합니다. 이 기록으로 어떤 파일을 어떤 조건에서 비교했는지 다시 확인할 수 있습니다.

### 7. 서비스에 사용할 모델을 비교하고 선택하는 방법

모델을 선택할 때는 먼저 서비스가 요구하는 조건을 정합니다. 한국어 문서 질의응답이라면 한국어 질문의 정답과 근거 사용이 중요하고, 정해진 JSON을 반환하는 서비스라면 내용과 필드 형식을 함께 평가해야 합니다. 사용할 GPU의 메모리와 허용할 대기 시간도 정합니다.

후보에는 원본 모델, GPTQ·AWQ 양자화 모델, 프루닝이나 증류를 적용한 모델을 넣을 수 있습니다. 같은 질문·시스템 메시지·대화 형식·생성 설정으로 평가하고, 입력 길이와 출력 길이를 함께 기록합니다.

| 확인할 내용 | 비교할 항목 |
|---|---|
| 답변 품질 | 정답 수, 요구한 출력 형식, 정오답이 바뀐 문항 |
| 예측 변화 | 같은 글의 PPL, 원본과의 1순위 토큰 일치율 |
| 메모리 | 로드 직후 사용량, 실제 요청에서의 최대값 |
| 답변 시작 | TTFT(첫 토큰 시간) |
| 답변 생성 | Decode 구간의 TPS(초당 생성 토큰 수) |

TTFT와 TPS는 서로 다른 사용 경험을 보여줍니다. 첫 토큰이 1.5초 뒤에 나오고 이후 50토큰/초로 생성된다면, 사용자는 처음 1.5초를 기다린 뒤 답변이 빠르게 이어지는 모습을 보게 됩니다.

검색한 문서를 입력에 붙이는 RAG 서비스는 Prefill이 길어질 수 있어 입력 길이별 TTFT가 중요합니다. 긴 글을 쓰는 서비스는 Decode가 오래 이어지므로 생성 속도가 전체 대기 시간에 크게 작용합니다. 사용자 수가 늘어나는 서비스에서는 대기열을 포함한 응답 시간도 측정합니다.

최종 비교는 **답변 품질 확인 → 메모리 조건 확인 → 실제 사용 조건의 시간 비교**로 이어집니다. 정답 수와 함께 질문 유형별 변화도 읽으면 어떤 업무에 적합한 후보인지 판단할 수 있습니다.

## 이해 확인

> [!question]- 노트북을 실행하면 어디에서 계산하나요?
> Runpod의 Python 커널이 코드를 실행하고 A40이 GPU 연산을 맡습니다. Mac의 브라우저는 입력과 출력을 주고받습니다.

> [!question]- 커널을 재시작했을 때 사라지는 것과 남는 것은 무엇인가요?
> 메모리의 변수·함수·모델이 초기화됩니다. 저장한 노트북과 `/workspace`의 모델·결과 파일은 남습니다.

> [!question]- 노트북의 모든 코드 셀에 실행 번호가 생기면 성공인가요?
> 실행 번호와 함께 오류 출력, 결과 행의 `error`, 최종 저장 파일을 확인합니다. 실행 번호는 해당 호출이 반환됐음을 보여 줍니다.

> [!question]- `group_size=128`과 보정 청크 128개는 각각 무엇인가요?
> 앞의 128은 같은 스케일을 공유하는 가중치 개수, 뒤의 128은 보정에 사용하는 문서 조각 개수입니다.

> [!question]- `"16bit"`로 GPTQ 파일을 평가하면 어떤 방식으로 로드하나요?
> 이 하네스에서는 NF4 변환을 추가하지 않고 파일에 저장된 양자화 설정을 읽습니다. 실제 구현은 층 이름과 커널 로그로 확인합니다.

> [!question]- Pod 사용을 마친 뒤에도 남을 수 있는 비용은 무엇인가요?
> 유지한 Network volume의 저장 요금입니다. 브라우저 종료, Python 커널 종료, Pod 종료는 서로 다른 조작입니다.

> [!question]- AWQ에서는 언제, 어떤 목적으로 활성값을 살피나요?
> 가중치를 낮은 비트로 바꾸기 전에 보정 문장을 통과시켜 살핍니다. 큰 입력과 곱해지는 가중치의 오차가 출력에 크게 반영될 수 있어, 중요한 채널과 적용할 배율을 정하는 데 사용합니다.

> [!question]- GPTQ는 이미 양자화한 부분의 오차를 어떻게 줄이나요?
> 보정 입력에서 구한 관계를 이용해 아직 양자화하지 않은 가중치를 조정합니다.

> [!question]- AWQ에서 가중치를 키우면서 입력을 나누는 이유는 무엇인가요?
> 두 배율을 상쇄해 양자화 전 계산 결과를 유지하기 위해서입니다. 이후 양자화한 출력의 오차를 비교해 배율을 고릅니다.

> [!question]- 양자화한 파일을 다시 로드해 평가하는 이유는 무엇인가요?
> 배포할 가중치·설정·토크나이저가 함께 작동하는지, 실제 GPU에서 어떤 커널로 얼마나 빠르게 계산하는지 확인하기 위해서입니다.

> [!question]- 긴 문서를 읽고 짧게 답하는 서비스에서는 어떤 시간을 먼저 살피나요?
> 입력 길이별 TTFT를 살핍니다. 문서를 처음 읽는 Prefill 시간이 답변 시작까지의 기다림에 영향을 주기 때문입니다.
