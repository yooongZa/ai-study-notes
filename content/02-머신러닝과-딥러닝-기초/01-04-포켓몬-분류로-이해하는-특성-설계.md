## 1. 특성 설계가 필요한 이유

- 표에 있는 정보를 어떤 형태로 모델에 전달하느냐에 따라 모델이 찾을 수 있는 규칙이 달라진다.
- 포켓몬의 이름은 문자열이지만, 이름의 길이나 특정 단어의 포함 여부는 숫자로 표현할 수 있다.
- Feature engineering(특성 설계)은 **예측에 도움이 될 정보를 입력값으로 표현하는 과정**이다.
- 이 예제에서는 포켓몬의 능력치·속성·이름을 이용해 전설의 포켓몬인지 분류하는 흐름을 살펴본다.

---

## 2. 포켓몬 분류의 입력과 정답

- 한 행은 포켓몬의 한 형태를 나타낸다. 같은 종류의 포켓몬도 형태가 다르면 여러 행으로 들어갈 수 있다.
- `Legendary`는 전설 여부를 나타내며 예측할 정답이다.
- `HP`, `Attack`, `Defense`, `Sp. Atk`, `Sp. Def`, `Speed`는 능력치다.
- `Total`은 여섯 능력치의 합이다. 개별 능력치와 함께 사용할 때는 같은 정보가 합계로도 표현된다는 점을 이해한다.
- `Type 1`, `Type 2`는 속성이고, `Name`은 이름이다.
- `Type 2`가 비어 있으면 두 번째 속성이 없는 포켓몬일 수 있다. 빈 값의 의미를 확인하면 적절한 표현을 고를 수 있다.
- `Legendary`는 입력 `X`에서 제외한다. 예측해야 할 정답을 입력에 넣으면 분류하는 방법을 배우는 목적이 사라진다.

---

## 3. 데이터에서 특성 후보를 찾는 방법

1. 전설·일반 포켓몬의 수를 비교한다.
2. 두 집단의 능력치 분포를 살펴본다. 높은 능력치가 어느 집단에 얼마나 있는지 본다.
3. 속성별로 전설 포켓몬이 차지하는 비율을 살펴본다.
4. 이름의 길이나 특정 단어가 집단을 구분하는 데 도움이 되는지 살펴본다.

- 이름을 바탕으로 규칙을 고를 때는 학습 자료 안에서 후보를 찾는다.
- 평가 자료의 전설 여부까지 보고 단어를 고르면, 평가에 사용할 답이 입력 설계에 미리 반영된다.
- 자료를 나눈 뒤 학습 자료에서 특성을 정하고, 정해진 규칙을 평가 자료에 그대로 적용한다.

## 4. pandas 문자열 메서드와 이름 특성 추출

### pandas Series의 str 접근자와 문자열 메서드

- 원래 문자열을 길이와 특정 표현의 포함 여부로 바꾸면 분류에 사용할 특성이 된다. 이 특성이 실제 예측에 도움이 되는지는 새 자료의 성능으로 확인한다.

**코드 예시**

```python
name_length = pokemon['Name'].str.len()
has_mega = pokemon['Name'].str.contains('Mega', regex=False)
```

**코드 해설**

- 이름이 `Mega X`라면 글자 수는 공백을 포함해 6이고, `Mega` 포함 여부는 `True`다. 문자열에서 분류 입력으로 쓸 수 있는 길이와 참·거짓 값을 각각 얻는다.

- `pokemon`은 포켓몬 표를 담은 `DataFrame`이라고 가정한다.
- `pokemon['Name']`은 이름 열 하나를 `Series`로 선택한다.
- `.str`은 열 안의 문자열을 다루는 기능에 접근하는 속성이다.
- 문자열 접근자의 메서드인 `len()`은 각 이름의 글자 수를 구한다.
- 같은 접근자의 메서드인 `contains()`는 각 이름에 지정한 문자열이 포함되어 있는지 확인한다.
- `regex=False`는 `'Mega'`를 문자 그대로 찾는다는 뜻이다. 결과는 행마다 `True` 또는 `False`다.

### re 모듈의 findall 함수의 활용

- 띄어쓰기가 없는 이름도 일정한 표기 규칙이 있으면 조각으로 나눌 수 있다. 아래에서는 대문자로 시작하는 부분을 하나의 조각으로 찾는다.

**코드 예시**

```python
import re

tokens = re.findall(r'[A-Z][a-z]*', 'CharizardMega X')
```

**코드 해설**

- 결과는 `['Charizard', 'Mega', 'X']`다.
- `[A-Z]`는 영문 대문자 한 글자다.
- `[a-z]*`는 소문자가 **0개 이상** 이어지는 부분이다. 소문자가 없어도 되므로 `X`도 잡힌다.
- `r'...'`는 역슬래시를 포함한 패턴을 적기 편한 Python 문자열 표기다.
- 이 패턴은 대문자로 시작하는 이름 조각을 찾는 예시다. 실제 이름의 표기 규칙에 맞춰 패턴을 정한다.
- `collections` 모듈의 클래스인 `Counter`는 조각별 등장 횟수를 센다. `Counter(tokens).most_common(3)`은 많이 등장한 순서로 최대 3개와 횟수를 반환한다.

## 5. 여러 속성의 원 핫 인코딩

- 속성마다 하나의 열을 만든다. 불 속성 열에는 불 속성이 있으면 1, 없으면 0을 넣는다.
- 두 속성을 가진 포켓몬은 두 열이 1이 된다. 이렇게 여러 항목을 동시에 표시하는 표현을 Multi-hot encoding(멀티 핫 인코딩)이라고 한다.
- 한 범주만 1인 원 핫 표현에서, 동시에 여러 범주를 표시할 수 있도록 확장한 형태다.

- 하나의 대상이 여러 속성을 가질 때는 속성별 포함 여부를 각각 표시한다. 첫 속성과 둘째 속성 중 어느 쪽에 불 속성이 있든 같은 Fire 열에 반영한다.

**코드 예시**

```python
pokemon['Fire'] = (
    (pokemon['Type 1'] == 'Fire')
    | (pokemon['Type 2'] == 'Fire')
).astype(int)
```

**코드 해설**

- 첫 속성이 `Water`, 둘째 속성이 `Fire`라면 두 비교 결과는 `False`, `True`다. `|`로 합치면 `True`, 정수로 바꾸면 1이 되어 불 속성을 가진 포켓몬으로 표시된다.

- `==`는 각 행의 속성이 `'Fire'`와 같은지 비교한다.
- `|`는 두 조건 중 하나라도 참이면 참으로 만드는 원소별 연산자다. 각 비교식을 괄호로 감싼다.
- pandas `Series`의 메서드인 `astype(int)`는 `True`와 `False`를 1과 0으로 바꾼다.
- 첫 번째 속성 또는 두 번째 속성이 불이면 `Fire` 열에 1이 들어간다.

## 6. 기준 모델과 새 특성의 효과 비교

- 먼저 능력치처럼 바로 사용할 수 있는 수치만으로 기준 모델을 만든다.
- 다음으로 이름과 속성에서 만든 특성을 추가한다.
- 같은 학습·평가 행, 같은 모델 설정으로 비교하면 입력 정보가 바뀐 효과를 살펴보기 좋다.
- `sklearn.tree` 모듈의 클래스인 `DecisionTreeClassifier`는 조건을 순서대로 적용하는 분류 모델을 만든다.
- 모델 객체의 `fit` 메서드는 학습 자료로 조건을 정하고, `predict` 메서드는 정해진 조건으로 클래스를 예측한다.
- 추가한 특성의 효과는 평가 결과로 판단한다. 어떤 특성이 도움이 되는지 알려면 하나씩 더하거나 빼면서 같은 기준으로 비교한다.

## 7. 클래스별 정밀도·재현율 해석

- 예를 들어 100개 중 전설이 10개, 일반이 90개라고 하자.
- 모두 일반이라고 예측하면 정확도는 90%지만, 전설 10개 중 찾은 것은 0개다.
- 전설을 찾는 목적이라면 전체 정확도와 함께 전설 클래스의 Precision(정밀도), Recall(재현율)을 확인한다.
- 정밀도는 전설이라고 예측한 대상 중 실제 전설의 비율이다.
- 재현율은 실제 전설 중 모델이 찾은 비율이다.

### sklearn.metrics 모듈의 classification_report 함수의 활용

- 희소한 클래스를 잘 찾는지 확인하려면 클래스별 오류를 따로 봐야 한다. 정밀도·재현율·F1을 함께 계산하면 놓친 사례와 잘못 고른 사례의 차이를 볼 수 있다.

**코드 예시**

```python
from sklearn.metrics import classification_report

report = classification_report(y_test, y_pred, zero_division=0)
```

**코드 해설**

- `y_test`는 실제 정답, `y_pred`는 예측한 클래스다.
- 출력에는 클래스별 정밀도, 재현율, F1 점수, 실제 데이터 수인 `support`가 들어간다.
- `zero_division=0`은 해당 지표의 분모가 0인 경우 0으로 표시하도록 지정한다.
- 모델 변경 후에는 전설을 더 찾았는지, 일반 포켓몬을 전설로 잘못 분류하는 경우도 늘었는지 함께 읽는다.

---

## 8. 특성 설계부터 효과 확인까지의 흐름

1. 무엇을 분류할지 정하고 정답 열을 분리한다.
2. 학습 자료와 평가 자료를 나눈다.
3. 학습 자료의 분포에서 특성 후보를 찾는다.
4. 이름과 속성을 숫자·참거짓 값으로 표현한다.
5. 기준 모델과 특성을 추가한 모델을 같은 자료에서 비교한다.
6. 찾고 싶은 클래스의 정밀도와 재현율로 변화를 해석한다.
