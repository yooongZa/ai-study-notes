## 1. 모델 평가 지표가 필요한 이유

- 모델을 바꾼 뒤 좋아졌는지 판단하려면 비교 기준이 필요하다.
- 오류마다 중요도가 다를 수 있다. 스팸을 놓치는 오류와 정상 메일을 스팸으로 분류하는 오류는 사용자에게 다른 불편을 준다.
- Metric(평가 지표)은 **어떤 결과를 잘한 것으로 볼지 수치로 정한 기준**이다.
- 목적에 맞는 지표를 정해야 모델의 성능을 의미 있게 비교할 수 있다.

---

## 2. 학습 손실과 평가 지표의 역할

- Loss(손실)는 학습 과정에서 줄이려는 값이다. 예측과 정답의 차이를 계산하고 가중치를 바꿀 방향을 구하는 데 쓴다.
- 평가 지표는 예측 결과가 목적에 얼마나 맞는지 설명한다.
- 회귀에서는 평균제곱오차를 손실과 평가 지표로 모두 사용할 수 있다.
- 분류에서는 교차 엔트로피로 학습하고, 정확도나 재현율로 결과를 해석할 수 있다.
- 정답 여부만 0과 1로 표시하는 정확도는 예측 점수가 조금 움직였을 때 변화를 세밀하게 반영하기 어렵다. 학습에서는 점수 변화에 따라 값이 변하는 손실을 사용한다.

---

## 3. 혼동행렬의 TP·FP·FN·TN

- 스팸을 찾는 문제에서 Positive(양성)는 스팸, Negative(음성)는 정상 메일이라고 정하자.
- 여기서 양성은 우리가 찾기로 정한 클래스다. 스팸 탐지라면 스팸 메일을 양성으로 정한다.
- Confusion matrix(혼동행렬)는 실제 정답과 예측을 함께 보고 건수를 나눈 표다.

| 결과 | 스팸 분류에서의 의미 |
| --- | --- |
| TP 참양성 | 실제 스팸을 스팸으로 찾았다. |
| FP 거짓양성 | 정상 메일을 스팸으로 잘못 분류했다. |
| FN 거짓음성 | 실제 스팸을 정상으로 판단해 놓쳤다. |
| TN 참음성 | 정상 메일을 정상으로 판단했다. |

- 예를 들어 메일 100개에서 `TP=15`, `FP=5`, `FN=5`, `TN=75`라고 하자.
- 실제 스팸은 `TP + FN = 20개`다.
- 모델이 스팸이라고 표시한 메일은 `TP + FP = 20개`다.
- 같은 20개여도 두 집합의 구성은 다르다. 스팸 5개를 놓치고 정상 메일 5개를 잘못 표시했다.

## 4. 정확도·정밀도·재현율·F1의 의미

### 정확도: 전체 예측 중 정답의 비율

$$\mathrm{Accuracy}=\frac{TP+TN}{TP+TN+FP+FN}$$

- 예시에서는 `(15 + 75) / 100 = 0.90`이다.
- 전체 예측의 정답 비율을 쉽게 읽을 수 있다.
- 특정 클래스가 드물면 그 클래스를 얼마나 찾았는지도 따로 확인한다.

### 정밀도: 양성으로 예측한 것 중 실제 양성의 비율

$$\mathrm{Precision}=\frac{TP}{TP+FP}$$

- 예시에서는 `15 / (15 + 5) = 0.75`다.
- 스팸이라고 표시한 20개 중 15개가 실제 스팸이다.
- 정상 메일을 스팸으로 잘못 처리하는 오류를 줄이고 싶을 때 정밀도를 살펴본다.

### 재현율: 실제 양성 중 찾아낸 비율

$$\mathrm{Recall}=\frac{TP}{TP+FN}$$

- 예시에서는 `15 / (15 + 5) = 0.75`다.
- 실제 스팸 20개 중 15개를 찾았다.
- 스팸을 놓치는 오류를 줄이고 싶을 때 재현율을 살펴본다.

### F1 점수: 정밀도와 재현율의 조화평균

$$F1=\frac{2PR}{P+R}$$

- `P`는 정밀도, `R`은 재현율이다. 두 값의 조화평균을 구한다.
- 둘 중 하나가 작으면 F1도 낮아진다. 예를 들어 정밀도 1, 재현율 0.1이면 F1은 약 0.18이다.
- 전부 스팸으로 표시해 재현율만 높이는 방식은 정상 메일도 많이 포함하므로 정밀도가 낮아진다.

## 5. 예측 확률과 분류 임곗값

- 분류 모델은 각 클래스의 점수나 확률을 계산할 수 있다.
- Threshold(임곗값)는 그 점수를 보고 최종 클래스를 정하는 기준이다.
- 스팸 확률이 0.5 이상이면 스팸이라고 결정하는 경우, 0.5가 임곗값이다.
- 임곗값을 낮추면 더 많은 메일을 스팸으로 표시한다. 실제 스팸을 더 찾는 대신 정상 메일도 더 포함할 수 있다.
- 임곗값을 높이면 스팸으로 표시되는 메일이 줄어든다. 잘못 표시한 정상 메일이 줄어드는 대신 일부 스팸을 놓칠 수 있다.
- 임곗값은 검증 자료에서 목적에 맞게 정하고, 테스트 자료에서는 정해 둔 기준으로 평가한다.

### sklearn 분류 모델의 predict_proba 메서드의 활용

- 분류 확률을 최종 클래스로 바꾸려면 판단 기준인 임곗값이 필요하다. 아래에서는 스팸 확률이 0.5 이상이면 스팸으로 표시한다.

**코드 예시**

```python
probabilities = model.predict_proba(X_test)
spam_score = probabilities[:, 1]
y_pred = (spam_score >= 0.5).astype(int)
```

**코드 해설**

- 메일 세 개의 스팸 확률이 `[0.2, 0.8, 0.6]`이면 비교 결과는 `[False, True, True]`이고, 최종 클래스는 `[0, 1, 1]`이다.
- 모델은 먼저 확률을 계산하고, 임곗값은 그 확률을 읽어 스팸 표시 여부를 결정한다.

- 이 예시는 `predict_proba`를 지원하는 모델이며 `model.classes_`가 `[0, 1]`인 경우다. 1을 스팸으로 정했다.
- `probabilities`의 형태는 `(메일 수, 클래스 수)`다.
- `[:, 1]`은 모든 행의 두 번째 열을 선택한다. 여기서는 스팸 확률이다.
- `>= 0.5`로 비교해 얻은 참거짓 값을 배열의 `astype(int)` 메서드로 1과 0으로 바꾼다.
- `decision_function`을 제공하는 모델은 확률 대신 분류 점수를 반환한다. 곡선을 계산할 때 이런 점수도 사용할 수 있다.

## 6. F-beta와 오류의 중요도 반영

- 놓치는 오류와 잘못 찾는 오류의 중요도가 다르면, 평가 점수에도 그 차이를 반영할 수 있다.
- F-beta는 정밀도와 재현율을 합칠 때 `beta`로 반영 비중을 조정한다.
- `beta=1`이면 앞에서 배운 F1이다.
- `beta=2`이면 재현율을 더 중요하게 반영하고, `beta=0.5`이면 정밀도를 더 중요하게 반영한다.

$$F_\beta=\frac{(1+\beta^2)PR}{\beta^2P+R}$$

- `P`는 정밀도, `R`은 재현율이다.
- 임곗값을 바꾸면 어떤 메일을 스팸으로 표시할지가 달라진다.
- `beta`를 바꾸면 **같은 예측 결과에 부여하는 평가 점수**가 달라진다.

### sklearn.metrics 모듈의 fbeta_score 함수의 활용

- F-beta는 정밀도와 재현율에 주는 비중을 조절하는 지표다. 같은 예측을 두 기준으로 채점하면 낮은 재현율이 점수에 미치는 영향을 비교할 수 있다.

**코드 예시**

```python
from sklearn.metrics import fbeta_score

y_true = [1, 1, 1, 1, 0, 0]
y_pred = [1, 1, 0, 0, 0, 0]

f1 = fbeta_score(y_true, y_pred, beta=1)
f2 = fbeta_score(y_true, y_pred, beta=2)
print(round(f1, 3), round(f2, 3))  # 0.667 0.556
```

**코드 해설**

- 실제 스팸 4개 중 2개를 찾았고, 정상 메일을 스팸으로 잘못 표시한 것은 없다.
- 정밀도는 1, 재현율은 0.5다.
- 재현율을 더 중요하게 반영한 F2는 이 낮은 재현율을 반영해 0.556이 된다.
- 코드를 보면 두 계산에 같은 `y_pred`를 전달한다. 달라지는 것은 평가 점수다.
- 평가에 사용할 `beta`를 정한 뒤, 검증 자료에서 그 지표가 좋은 임곗값을 선택한다.

## 7. PR·ROC 곡선과 여러 임곗값의 평가

- Precision-recall curve(정밀도 재현율 곡선)는 임곗값을 바꾸면서 정밀도와 재현율이 어떻게 변하는지 그린다.
- 가로축은 재현율, 세로축은 정밀도다. 많이 찾으면서 잘못 찾는 경우도 적은 모델은 두 값을 높게 유지한다.
- AP(Average precision, 평균 정밀도)는 재현율이 늘어난 구간의 정밀도를 가중 평균한 값이다.
- ROC curve(수신자 조작 특성 곡선)는 가로축에 거짓양성률, 세로축에 참양성률을 놓는다.
- 거짓양성률은 `FP / (FP + TN)`이다. 실제 정상 메일 중 스팸으로 잘못 표시한 비율이다.
- 참양성률은 재현율과 같으며 `TP / (TP + FN)`이다.
- ROC AUC는 ROC 곡선 아래 면적이다. 양성에 음성보다 높은 점수를 부여하는 순위 구분 능력을 요약한다.
- 양성과 음성의 점수를 무작위로 정하면 ROC AUC는 평균적으로 0.5에 가깝다. 완전히 구분하면 1이다.
- 양성이 드문 문제에서는 정밀도 재현율 곡선을 함께 보면, 양성으로 고른 대상에 오탐이 얼마나 섞이는지 읽기 좋다.

### sklearn.metrics 모듈의 혼동행렬·F1·AP·AUC 함수

- 최종 클래스의 정답 여부와 점수의 순위는 서로 다른 평가 정보다. 혼동행렬·F1에는 선택한 클래스를, AP·ROC-AUC에는 양성에 준 연속 점수를 사용한다.

**코드 예시**

```python
from sklearn.metrics import confusion_matrix, f1_score
from sklearn.metrics import average_precision_score, roc_auc_score

matrix = confusion_matrix(y_test, y_pred, labels=[0, 1])
f1 = f1_score(y_test, y_pred, zero_division=0)
ap = average_precision_score(y_test, spam_score)
auc = roc_auc_score(y_test, spam_score)
```

**코드 해설**

- 네 함수는 **같은 평가 자료**의 정답과 예측을 짝지어 받는다. `y_test`, `y_pred`, `spam_score`는 길이와 메일 순서가 같아야 한다. 앞의 F-beta 예시와는 별도의 평가 자료를 사용한다고 가정한다.

- `confusion_matrix`는 행에 실제 클래스, 열에 예측 클래스를 놓는다. 위 순서에서는 `[[TN, FP], [FN, TP]]`가 된다.
- `f1_score`에는 최종 클래스인 `y_pred`를 전달한다.
- `average_precision_score`, `roc_auc_score`에는 연속된 점수인 `spam_score`를 전달한다. 여러 임곗값에서의 구분 능력을 계산하기 때문이다.
- `roc_auc_score`를 계산하는 평가 자료에는 양성과 음성이 모두 있어야 한다.

## 8. 목적에 맞는 지표와 임곗값 선택

1. 찾을 클래스를 정한다.
2. 놓친 오류와 잘못 찾은 오류 중 어떤 문제가 더 큰지 정한다.
3. 혼동행렬로 실제 건수를 확인한다.
4. 정밀도·재현율과 목적에 맞는 F 점수로 오류의 비율을 읽는다.
5. 점수와 곡선을 보고 임곗값을 정한다.
6. 고정한 모델과 임곗값을 테스트 자료에서 평가한다.

## 9. 다중 분류의 클래스별 평가와 평균

- 고양이·개·새처럼 정답 종류가 세 개 이상이면 Multi-class classification(다중 분류)이다.
- 종류마다 예측 성능이 다를 수 있으므로, 각 클래스를 기준으로 정밀도·재현율·F1을 구한다.
- 예를 들어 고양이의 재현율은 실제 고양이 중 고양이로 맞힌 비율이다.
- 여러 클래스의 결과를 하나의 값으로 나타낼 때는 평균 방식을 정한다.

### 9-1) macro·weighted·micro의 계산 기준

- `macro`: 클래스별 점수에 같은 비중을 준다. 고양이·개·새가 각각 평균의 3분의 1을 차지한다.
- `weighted`: 실제 데이터 개수에 비례해 클래스별 점수를 합친다. 자료가 많은 클래스의 영향이 커진다.
- `micro`: 모든 클래스의 TP·FP·FN을 먼저 합친 뒤 점수를 계산한다.
- 한 자료에 정답 하나를 붙이는 다중 분류에서 모든 클래스를 포함하면, micro F1은 정확도와 같다.
- 종류별 성능을 같은 비중으로 보고 싶으면 macro를, 실제 자료의 비율을 반영하고 싶으면 weighted를 사용한다.

### 9-2) sklearn.metrics 모듈 f1_score 함수의 average 인자

- 클래스 수가 여러 개이면 먼저 클래스별 성능을 구하고 이를 평균한다. 클래스마다 같은 비중을 주는 방식과 데이터 수를 반영하는 방식은 다른 질문에 답한다.

**코드 예시**

```python
from sklearn.metrics import f1_score

truth = [0, 0, 0, 0, 1, 2]
predicted = [0, 0, 0, 0, 0, 0]
for average in ["macro", "weighted", "micro"]:
    value = f1_score(truth, predicted, average=average)
    print(average, round(value, 3))
```

**코드 해설**

- 반복문은 같은 `truth`와 `predicted`를 유지하고 `average`만 바꾼다. 매번 계산한 F1을 출력하므로 세 평균 방식의 차이를 직접 비교할 수 있다.

- 0·1·2는 클래스 번호다. 모델은 여섯 자료를 모두 0으로 예측했다.
- 클래스 0의 F1은 0.8이고, 클래스 1과 2의 F1은 각각 0이다.
- macro는 `(0.8 + 0 + 0) / 3`으로 약 **0.267**이다.
- weighted는 `0.8 × 4/6 + 0 × 1/6 + 0 × 1/6`으로 약 **0.533**이다.
- micro는 전체 여섯 개 중 네 개를 맞힌 비율과 같아 약 **0.667**이다.
- 같은 예측 결과라도 ‘클래스에 같은 비중을 줄지, 데이터 개수를 반영할지’에 따라 값이 달라진다.
